文件维护与复现说明

仓库维护目录为 hardware/、tools/、docs/。作者工作目录中的原始 work/、outputs/ 和临时文件不纳入 Git；以后要同步到 GitHub 的修改应落在仓库维护目录并提交。

.epro、.esch、BOM 和审阅 PDF 可直接使用。脚本记录了设计生成过程，本次入库只校验脚本语法和文件完整性，没有重新运行全套电路生成、EDA DRC 或硬件测试。

Python

python -m pip install -r requirements.txt

原脚本使用 Python 3.12 开发。部分 PDF 渲染脚本使用 Windows 字体路径，需要相应字体或自行调整。运行命令以仓库根目录为当前目录。

原理图生成保留 v0.1 → v0.2 → v0.3 的依赖关系。主要入口：

  • tools/schematic-v0.1/build_schematic.py
  • tools/schematic-v0.2/build_barechip.py
  • tools/schematic-v0.3/build.py：v0.3 正式生成入口；同目录 build_schematic.py 是中间快照，不应作为独立入口。
  • tools/schematic-v0.3/audit.py：模型与封装校核。
  • tools/footprint-size-review/review.py：读取保存工程并计算封装占位。

生成脚本需要原始厂商工程输入。按脚本中的文件名及 资料来源 取回 SiFli 官方 EDA/PADS 工程、器件规格书，以及 ADI 评估板 ODB++ 文件，放入相应 tools/*/references/ 目录。部分提取后的 JSON、网络清单和 .asc 文件也属于生成输入；它们没有随着缓存目录入库，因此当前不是一键可重建项目。

屏幕和连接器评估脚本使用的供应商 PDF 放在仓库根目录 references/vendor/，由使用者自行取得。各脚本或 config.json 中记录所需文件名。现有磁吸连接器封装均是独立草稿，未因此自动集成到手表主板。

BOM 工作簿脚本

tools/bom-selection/ 和 tools/reassessment-v0.3/ 下的 .mjs 依赖未随仓库发布，普通 Node.js 环境不保证可直接执行；已生成的 .xlsx 文件可用 Excel 或兼容软件打开。

校验记录

硬件目录内的 validation-*.json 是原设计阶段的记录，不是每次 Git 提交都会自动执行的检查。在线主板 PCB 的保存状态不能从本地原理图文件中重建。对电路做修改后，应重新进行原理图检查、网表同步、PCB 检查及必要的实物验证。
