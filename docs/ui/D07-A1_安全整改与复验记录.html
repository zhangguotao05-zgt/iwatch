三项整改

1. EPIC 临时字形缓冲

生产 _draw_epic_letter() 原来使用普通 lv_draw_buf_create()。对真实入口注入第一次分配失败得到 asserts=1, oom=0，与审批发现一致。本次改为受控的 lv_draw_buf_try_create_ex()，覆盖描述符和像素缓冲两个分配分支；失败时不提交 GPU，并通过 lv_tiny_ttf_report_draw_oom() 通知字体 owner 锁存故障。接口先验证字体回调身份，避免把非 TinyTTF 的私有数据解释为 TinyTTF 描述符。

全局断言保持启用，普通缓冲接口的既有行为保持兼容。foreground.data_size = mask_stride * glyph_height 的缓存同步修复保留。SDK 变更仍纳入十二文件白名单补丁，固定 SDK 不修改。

2. 绘制安全点回收

app_clock_main_process_font_fault() 只在 GUI 线程、LVGL 回调之外执行。故障待处理且 GPU/LCD 未空闲时返回等待状态，GUI 主循环保留输入采集和服务处理，但暂停 lv_timer_handler()，防止继续提交页面绘制。lv_refreshing_done() 确认空闲后才消费故障。

回收复用幂等 on_stop()：标记停止、取消输入、移除 tileview 回调、摘链并停止/反初始化表盘插件、删除状态栏控件、销毁字体缓存、删除 tileview、清除上下文并释放管理器，最后显示预创建应急层。不会在字体绘制或内存失败回调内删除对象。新增编译约束要求 LV_USE_OS == LV_OS_NONE，避免以后切到异步 LVGL 绘制线程后静默沿用当前回收假设。

应急层使用内置 Montserrat 20 位图字库，显示阶段不创建控件或替换文本。应用框架仍保留当前 clock 页面身份，既有 Home 按键路径可切回桌面，重复停止为空操作，重新进入重新建立页面和字体。故障锁存不是永久禁止进入。

3. 正式字体输入门槛

更新正式 DroidSansFallback.subset.json，绑定当前输入文案源文件哈希。generate_font_subset.verify_committed() 只读校验批准的源字体、实际十条通知字符串、规划字符、正式子集与正式清单。遗漏字符、文案变化、字体损坏或清单过期会报错，不自动刷新清单绕过检查。

GCC、Keil 共用的 build_identity.source_snapshot() 在构建开始、完成及归档复核时调用该门槛；正式回归先对仓库字体和清单执行确定性 --check，再测试临时产物。构建门槛不依赖 FontTools；可复现字体生成与逐字度量比较使用固定 FontTools 4.65.0。

长文滑动基线

固定场景为 SF32LB58 A128、390×450 QSPI AMOLED、当前 GCC 镜像、80% 亮度、通知页“我们是谁”长正文，上下往返滚动约 20 秒。记录首次进入和重复进入，区分滑动区间与首尾静止区间。

使用固定 SDK 现有 lcd_ctrl fps 1 打开统计，结束后执行 lcd_ctrl fps 0。驱动每个大于 2 秒的窗口输出 fps、flush_time[min~max] 和错误计数。此处 fps 是 LCD 绘制/传输完成次数率，可能包含局部更新，不等同于完整 GUI 帧率或 OLED 扫描率。flush_time 来自 rt_tick_get()，本配置 1000 tick/s，1 tick = 1 ms；窗口整数秒和静止间隔会影响显示值。

本轮保存传输侧原始窗口和现场交互描述，作为后续相同场景的可复现基线。没有增加 30 FPS 放行线；输入 P95 只报告队列延迟，不代替刷新指标。全面排版、分配、缓存和传输优化仍安排在主要 UI 页面成型后。

本次基线：80% 亮度操作段取得 16 个驱动窗口。首个窗口包含此前静止间隔，速率为 0，保留原值但不用于滑动比较；其余 15 个窗口完成次数率为 6–31 次/秒，flush_time 总范围 1–32 ms，驱动错误计数均为 0。原始日志前缀从 GTimer 6,302,118 到 7,393,715，按 32,768 Hz 换算跨度约 33.31 秒。

这些窗口覆盖进入、导航、正文滑动及退出动画，未按触摸手势隔离纯正文的 20 秒片段，因此仅作为本次混合操作的传输基线，不据此计算纯正文平均 FPS 或单帧 P95。用户对文字、操作和停顿询问回复“正常”。统计已用 lcd_ctrl fps 0 关闭，后续专项优化应固定手势轨迹并补完整 GUI 帧完成计量。
