缺陷和最小修复

固定 SDK 的 FT6146 read_point 在 I²C 失败、点数超过 2、保留事件时可能不写输出，却与合法末条 DOWN/UP 一样返回 RT_EEMPTY。原采样线程在调用后无条件消费 msg，第一次失败涉及未初始化读取；合法 DOWN 后失败则确定性保留旧样本，去重并不能取消正在进行的手势。

生产只改 iw_drv_touch.c：每轮完整初始化为 TOUCH_EVENT_NONE；将支持的本轮事件与返回码的继续采样语义分开，RT_EOK/RT_EEMPTY 的 DOWN/UP 均有效。无效输出或非预期错误清空待消费队列，last_rec.event 置 NONE，使旧 UP 不能作为释放证据；进入 cancel_pending/wait_release，复用 GUI 的 reset/wait-release 及读后取消检查。已隔离时连续失败仅撤销释放证据和饱和累计 discarded，不重复唤醒。失败结束当前批读取，保留原采样节流。

last_rec=NONE 是驱动私有的“未知、不可放行”状态，不排入 GUI 队列；既有 physical_down 快照此时保守为 true，不代表确认了物理按压。恢复需 GUI 已消费取消，且最近一次失效后出现可信 UP，之后没有 DOWN/再失败推翻。没有正常 UP 入队来伪造 click，没有动态分配、新公共接口或统计结构变化；互斥锁外才唤醒，LVGL 仍只由 app_watch 操作。

执行链与确定性回归

主机原样编译生产完整 tp_read_thread_entry、队列/touch_read、GUI bridge/全局取消、实际 LVGL，以及锁定 SDK read_regs/read_point。I²C 替身只提供 14 字节包/短传输，RTOS 替身只提供互斥检查、有限 IRQ 脚本及交错时点；在下一次阻塞等待处退出测试线程，不改 msg 寿命或生产分支。额外回调适配仅改变“还有点”的返回值，用于 RT_EOK 契约测试，不复制解码算法。
