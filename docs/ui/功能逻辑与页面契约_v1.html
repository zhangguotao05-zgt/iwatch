功能逻辑与页面契约 v1

2026-09-15 · 离线首批实现规范 · 状态：设计已明确，产品页面尚待开发

本文将 完整界面覆盖计划 收敛为可逐项开发的功能契约。页面 ID、状态、数据源与返回规则在此统一；代码实现与验收顺序见 模块接口与开发任务。容量和交互阈值是本项目首期设计值。

D10 的七页画面、坐标和状态呈现已在界面复刻定稿 v2定稿。补充入口：表盘可快捷进入设置、显示或关于，返回保存的来源；显示父页与亮度详情共用同一亮度服务和控件；校时字段编辑属于同页子态。既有 page_id、命令回执、数据有效性及资源所有权保持不变。

1. 功能深度与数据来源

深度适用功能界面与行为
本地真实业务时间、设置、秒表、计时器、闹钟、日历浏览、计算器、已导入照片。使用实际时钟和用户操作；持久化未就绪时标记“仅本次有效”。无 RTC 有效性时不能伪造正确日期。
硬件条件业务心率、血氧、活动、运动数据、电量、振动、抬腕。只有对应适配完成并返回有效数据才显示实测值；否则进入无硬件、采集中或故障状态。
离线展示天气、通信、地图、钱包、在线媒体等。可保留原计划中的页面层级；样例带“演示”标识，不进入真实健康历史、通知和计时记录，不显示已付款/已发消息等实际成功状态。

数据对象分开保存 capability、source 和 quality。设备可用不代表当前样本有效。切换演示模式时切换数据命名空间、取消相关页面请求和刷新快照；真实运行中的计时器仍留在实际服务中，不能被样例覆盖。

同一套 View/Presenter 接收不同 Provider 的快照。禁止为演示页另写一套页面；样例种子、时间和文本固定，便于复现视觉差异。

3. 输入、导航和弹层优先级

物理输入先变成统一语义，再由当前上下文分配给系统或页面。优先级从高到低：恢复/关机执行阶段 → 水锁解锁识别 → 系统输入锁 → 关键提醒弹层 → 普通弹层 → 页面编辑/滚动 → 表盘全局手势。一个输入只由一个所有者消费。

场景行为冲突处理
表冠单击表盘→桌面；App→桌面；桌面→表盘。叠放、切换器或普通覆盖层优先关闭至来源。有双击功能时单击导航等 280 ms 窗口结束；按下视觉反馈立即发生。
表冠双击 / 侧键双击切换器 / 钱包离线入口。不先执行单击行为；双击是两次完整按下释放，不能由重复边沿凑出。
侧键单击打开或关闭控制中心。关键提醒显示期间仅隐藏该弹层，提醒仍待确认；M1 未实现控制中心时不产生错误路由。
表冠旋转按当前控件焦点滚动、数值编辑或缩放；表盘向上进入叠放。一帧合并带符号增量，限幅；手指拖动优先，释放后下一次完整旋转再接管。
触摸拖动 / 长按超过 12 px 转为拖动，取消待点击与长按；触摸长按初值 500 ms。可滚动容器拥有手势，只有从表盘指定区域开始的上下滑才触发系统页。手指跨页面不得产生新页面点击。
返回遇到转场保留一个高优先级返回意图；先收敛当前转场再执行。重复返回合并；新的普通导航返回 BUSY。任意帧中断是后续验证项目。
水锁触摸全部消费，物理表冠连续按住 2 s 解锁，显示进度。解锁手势不同时触发 Siri/桌面；传感器、计时器继续；缺少旋钮时开发板 KEY1 承担按压。
提醒期间 Home关闭视觉覆盖回来源页，保留待确认图标及提醒记录。响铃默认最长 30 s 后停声，记录仍待确认；用户可在提醒页显式停止。

SDK 的 PRESS/RELEASE 与 CLICK/LONG 不能重复用于两套识别器。M1 以按下/释放与单调时间识别语义，忽略同一路 SDK 已合成的 CLICK/LONG；旧 M0 Home 快捷路径同步退出。KEY1、KEY2 各自持有状态，溢出时取消全部组合并取得一次可信释放状态后重新接收。具体实现与测试编号见接口文档。

物理长按初值：普通表冠 800 ms、侧键菜单 1500 ms、水锁退出 2000 ms；这些与触摸长按分别配置。软件注入和实物输入走同一仲裁器。缺少真实表冠时，普通列表和设置仍可全触摸操作。

参考基础语义：watchOS 26 按钮与手势、App 与主屏幕切换。上述仲裁、离线行为和阈值为项目实现约定。

4. 表盘、桌面与组件

数字表盘用一个时间快照同时生成日期、小时、分钟，避免跨午夜出现两套日期。秒钟变化只刷新秒字段；无效时间显示“--:--”与校时入口。演示模式可显示固定 10:09，但必须保留演示标识。电量无来源时显示未知，不展示固定满电。

首个表盘插件包括 create / resume / pause / destroy / apply_snapshot。暂停移除秒刷新定时器和动效，恢复按当前时间绘制，不补跑遗漏的帧。颜色/复杂功能编辑保存在草稿，确认后提交配置；取消恢复原主题。

桌面 App 清单来自固定注册表，只有一个稳定 App ID。列表先支持真实入口与不可用反馈；蜂窝桌面复用同一清单和路由。图标缩放与点击命中使用同一坐标变换，拖动结束后不立即启动最近图标。切换列表/蜂窝保留 App 选择但不共享控件指针。

组件展示页至少包含正常、按下、禁用、忙、错误、长中文和最大字号七组场景。原子组件不订阅服务；Presenter 持有订阅并将完整显示模型传入组件。度量单位、数值有效性和颜色语义不由每个 View 自己猜测。

5. 设置与亮度的完整闭环

设置字段分为 desired、applied、persisted 三个版本。desired 是希望设置的值，applied 是硬件/系统实际接受的值，persisted 是已确认写入存储的值。三者不能用同一个布尔“保存成功”代替。

输入 / 状态逻辑页面结果
进入亮度页读取当前 applied 值和能力；显示请求版本。没有驱动时禁用控制并说明不可用。
连续拖动范围初值 5–100；最多 20 Hz 发预览，同键合并最新值。释放时提交最终值。拇指位置可立即反馈；实际数值由执行回执确认，不把每次移动写闪存。
成功显示所有者在空闲边界应用；服务更新 applied 及其版本。会话模式显示“仅本次有效”；M4 存储提交确认后清除该提示。
BUSY / 超时 / 失败未受理时保留原 applied；已受理超时先查结果账本；驱动失败保留最后成功值。结束无限等待，允许再次操作；失败回到有效值。
处理期间返回页面 generation 失效，服务请求继续收敛；完成后只更新模型。再次进入读取最新值，不弹回旧页。
恢复亮屏使用用户 applied 值；手电筒亮度作为暂时覆盖另存。关闭手电筒/唤醒不会把亮度恢复成示例固定 100%。

亮度 5 的硬件效果需实测后校准，界面百分比不等同于实际亮度线性百分比。M1 持久化不可用，因此应诚实保持会话状态；M4 使用 500 ms 防抖合并保存，每字段一次写入保存最终值。

日期时间首期支持 2000–2099、公历、24/12 小时格式与固定 UTC 偏移，默认 UTC+08:00。日期和时刻一次提交；月末、闰年检查在 core 层。暂不包含自动夏令时规则；世界时钟只显示已支持时区，不把固定偏移标为全年自动校正。

6. 计时器状态机

最多 8 个同时存在的计时器，持续时间 1 s–24 h，内部使用 64 位单调毫秒；输入持续时间使用 u32 ms。页面保存草稿，服务分配稳定的 timer_id 和 revision。剩余时间每次按期限计算，不能每秒减一。

原状态 + 事件新状态 / 计算副作用
草稿 + START(duration)RUNNING；deadline = accepted_mono + duration。先保留提醒槽再受理；队满或容量满返回错误且不创建。
RUNNING + PAUSE，尚未到期PAUSED；remaining = deadline − now。取消到期调度，保留提醒槽。
PAUSED + RESUMERUNNING；deadline = now + remaining。重新登记最近期限。
RUNNING + now ≥ deadlineEXPIRED；remaining = 0，revision 增加。创建一次对应 occurrence 的提醒；渲染刷新不重复触发。
RUNNING / PAUSED + CANCELCANCELLED，然后回收活动槽。取消期限和预留提醒槽；页面回列表，最多 8 条最近摘要单独保存。
EXPIRED + ACK_ALERTACKNOWLEDGED，然后回收活动槽。停止该提醒声音/振动；只保留最多 8 条最近计时摘要。
EXPIRED + RESTART先原子确认旧提醒，再启动新一轮 occurrence。一个请求完成两步；重试不得创建两轮。
重启 + 已保存检查点有可信 RTC/连续性证据则按恢复策略重建；否则 RECOVERY_PENDING。只在恢复确认后再次计时；M1–M3 没有持久化时明确不恢复。

服务一轮先把 now 之前应到期的任务推进，再处理用户命令。因此暂停命令恰好在 deadline 到达时，先进入 EXPIRED，PAUSE 返回状态冲突并展示提醒。取消到期提醒必须使用 ACK_ALERT，不能用一个迟到的 PAUSE 静默吞掉到期事件。

修改 RTC 不改变运行中计时器期限；退出页面、切换表盘、打开设置都不停止服务。M4 睡眠恢复的单调补偿必须通过实测，不能用 GUI 定时器维持期限。

RESTART 复用该计时器槽，递增 occurrence；CANCEL/ACK 后槽可复用但旧实体 ID 不再分配。计时器 ID 与 occurrence 达到类型上限时明确拒绝新增/重开，不能静默回绕。到期提醒仍未确认时占用该计时器名额，以免后台无限积累。

7. 秒表

模型为 state、accumulated_ms、segment_start_ms、laps[100]。RUNNING 时显示 accumulated + now − segment_start；PAUSED 时显示 accumulated。START/PAUSE/RESET 都由服务串行执行，View 仅选择刷新频率。

  • 首次开始：IDLE→RUNNING；暂停累加当前段；继续创建新段，不覆盖累计值。
  • 重置仅允许 IDLE/PAUSED；RUNNING 的 RESET 返回 STATE_CONFLICT，避免误触丢失正在计时。
  • 计次只允许 RUNNING，每项保存累计和分段时间。100 项满时停止新增计次并给出提示，主计时继续。
  • 关闭页面继续计时；显示暂停并非业务暂停。重启无法证明连续计时时显示恢复待确认，不凭 tick 差值继续。
  • 记录精度为毫秒；显示精度和刷新率按场景限流，不能声称显示百分秒就有对应测量精度。

8. 闹钟与全局提醒

最多 16 个闹钟，字段包括稳定 ID、时分、星期重复掩码、是否启用、标签和最近触发 occurrence。每个启用闹钟预留一个提醒槽；8 个计时器加 16 个闹钟共 24 槽，避免同时到期互相挤掉。

场景明确处理
一次性 / 重复一次性触发后关闭调度但保留响铃记录；重复项计算下一有效本地日期。编辑产生新 revision，不重用上一 occurrence。
多项同时到期都进入提醒账本；按首次到期的 mono 时间、source_type、实体 ID 排序。闹钟的 UTC 期限先换算为当前单调时间域，不能拿 UTC 与计时器 mono 直接比较。只显示一个交互弹层，确认当前项后显示下一项。
通知队列满提醒保存在服务账本，唤醒只是提示。UI 重新读账本能找回全部待确认项。
重复闹钟长期未确认同源记录合并，保留首次排序时间、最近 occurrence 与饱和累加的 missed_count；不无限新增提醒。ACK 必须匹配最新 occurrence，旧页面的 ACK 返回冲突并刷新，不能清掉新发生。
稍后提醒初值 9 min，使用单调期限；关闭原发生的声音，保留同源提醒槽。稍后与常规调度同时到期只产生一次输出，清除本次稍后期限并计算下次常规调度。
禁用 / 删除禁用撤销未来与稍后调度，但已经产生的待确认记录保留。删除确认文案说明会同时停止该闹钟的当前提醒；服务原子确认、撤销调度并释放模型/提醒槽，旧回调不得复活该实体。
手动调时 / 时区变化增加 clock_revision，重新计算未来到期；不补响跨过的大段历史。相同已触发 occurrence 不再次响铃，并显示时间已更改提示。
正常唤醒迟到有可信时间且迟到 ≤60 s 时补交当前发生一次；更早的过期事件记为错过，先不连续补响。阈值为项目策略。
无 RTC / 无输出硬件无可信墙上时间不启用日历闹钟，保留设置草稿；没有马达/扬声器仍显示视觉提醒并报告输出能力缺失。

提醒状态为 PENDING→PRESENTING→ACKNOWLEDGED；自动停声、隐藏覆盖层、从通知列表删除普通通知都不等于确认提醒。震动/声音有单独输出管理器，取消后不能让旧 DMA/延迟回调重启输出。

每个闹钟配置 revision 保存已触发本地日期的高水位。同一配置在回拨到该日期或更早日期时不再次触发；不会只比较“上一条发生”而遗漏跨多日回拨。重新编辑并确认配置产生新 revision，界面提示新的下次触发日期。持久化阶段连同调度水位一起保存；重启无可靠历史时执行恢复确认策略。

输出管理器每个发生最多启动一轮、最长 30 s；正常情况下合计只有一个声音/振动输出源。勿扰仅抑制普通通知，用户设置的计时器与闹钟仍进入关键提醒流程；静音关闭声音但保留可用的振动和视觉。没有对应输出硬件时只显示视觉，不把驱动缺失当成已发声。

9. 系统壳层

控制中心：每项控制声明其所需能力。勿扰、文字大小、减少动态效果可做本地设置；蓝牙/联网关闭阶段不显示虚假连接；电量读数不可用时显示未知。水锁和手电筒使用独立临时状态，退出需恢复原亮度与触摸仲裁。飞行模式若展示，只反映实际无线配置。

通知：固定 32 条普通通知，按接收序号排序，未读/已读/删除互斥；打开详情才标记已读。文本槽为 256 B（含终止零），UTF-8 只在完整码点边界截断；详细消息可引用有上限的内容句柄。容量满先回收最早已读，再回收最早普通通知并计数。关键提醒使用独立 24 槽账本。

智能叠放：最多 8 张卡片；活动提醒→进行中的计时/运动→固定卡片顺序稳定排序，相同等级不因每秒更新抖动。首期采用确定性规则，不模拟预测能力。进入卡片详情复用原 App ID。

切换器：保存最多 6 个历史 App ID、最近页面参数和缩略图句柄；SiFli 最多 2 个 App 运行对象。选择已销毁 App 时从快照重建；关闭卡片只撤销页面资源，不能自动取消计时器/运动。缩略图预算不足时回退为图标和名称。

锁屏与水锁：锁屏 M3 先实现手动输入锁及受控解锁流程；没有佩戴检测时不承诺摘腕自动锁定。密码输入的视觉示例属于演示模式，实际密码存储、尝试限制、重启恢复和调试口边界另列安全任务。水锁不提供防水保证，也不模拟不存在的排水硬件效果。

10. 健康与运动的数据闭环

功能状态与输入输出约定

血氧空闲→佩戴检查→测量→完成/超时/取消；测量超时由适配声明。结果包含 SpO₂、质量、时间与来源；失败显示原因和重试，不填入随机正常值。退出手动测量页默认取消该会话。

体能训练READY→COUNTDOWN→RUNNING↔PAUSED→FINISH_CONFIRM→SUMMARY；最多 1 个活动会话。倒数可取消；结束前保留继续入口；后台运行保留单调计时。无 GPS 时距离/轨迹不可用，无心率时不画真实心率曲线。
传感器断连适配发布 fault，有限次数恢复后保持故障。运动计时可继续；受影响指标变无效；新会话不能默默复用旧传感器句柄。

原始 PPG、算法输出和 UI 摘要是三类缓冲。初期调试原始波形优先串口导出，UI 图表只留定长降采样历史；不能在 GUI 线程运行 PPG 算法或逐样本写闪存。MAXM86146 的外部 LED、供数格式、算法固件和光学结构在硬件任务验证后再启用真实 Provider。

日期被向后调整时不让当天累计值倒退或重复入库：保存采样会话 ID、累计计数起点与日桶 revision，重新分桶使用明确的校时事件。首期可以标记当天“时间已调整”，不自动虚构缺失历史。

12. 首批端到端验收故事

  1. 首次开机：RTC 无效→待校时表盘→手动设置→有效表盘。返回和复位不应恢复成 2022 年。
  2. 调整亮度：表盘→应用列表→设置→显示→亮度；连续拖动→最后值实际生效→返回；存储不可用时显示会话值。
  3. 后台计时：启动 10 s 计时器→回表盘→打开设置→到期提醒→停止→重新进入列表，无重复记录。
  4. 多重提醒：8 个计时器和 16 个闹钟同刻到期→保留 24 个源→依次确认；普通通知删除不能清空关键提醒。
  5. 输入竞争：拖动列表时连续双击表冠、侧键、水锁退出→一个输入只触发一个语义，最终可回表盘。
  6. 迟到回执：提交设置→立即退出并重新进入同名页→旧 generation 不更新控件；全局消费者仍确认并回收结果，新页从模型得到实际值。
  7. 缺失硬件：健康、电池或马达未接入→状态正确且可返回；演示切换不写真实历史。
  8. 低内存：目标页或缩略图分配失败→收敛到当前页/轻量错误层→释放后台缓存→可再次操作。

每次故事记录构建 ID、输入序列、预期/实际状态、相关日志和实屏图片。通过页面截图不能替代后台状态与清理检查。
