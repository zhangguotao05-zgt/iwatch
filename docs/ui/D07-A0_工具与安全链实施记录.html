3. 双工具链资源计量

resource_budget.py 先验证 build_identity.json 中 main、map 和 ELF/AXF 哈希，再按工具链读取实际链接结果。GCC 从 ELF 节表统计 TTF 和图片，并用 map 输入段交叉核对；Keil 从 armlink map 的输入段、字体符号和 Image component sizes 交叉核对。错误工具链、陈旧产物、重复或未分配节、截断 ELF/map 均拒绝。

4. SDK 补丁管理

固定 SDK 本体保持在 421126d9f476ed8e2a6f0b0ca28a9f241c182e65 且工作树干净。sdk_patch.py 从该提交创建 detached 派生 worktree，应用版本化补丁并核对 11 个允许文件、补丁后文件哈希、反向可应用性和无额外修改；路径逃逸、未知文件、手工改动或补丁漂移都会失败。半应用 worktree 会通过 Git worktree 命令回收。

补丁 SHA-256 为 ac5eb8a5935e3d8e6b26ca845a2d6dbe28cc7ad4b46df48093afe91a0a7c233a。构建身份现在区分 base 与 patched：基础 SDK 记录干净状态；派生 SDK 记录固定提交、补丁哈希和全部补丁后文件哈希。两种状态以外的 SDK 均不能生成合法身份。

补丁保留 LVGL 普通分配 API 的致命断言，只给 tiny_ttf 增加可恢复的 cache、红黑树节点和绘制缓冲路径。字体构造任一步失败会逆序释放部分对象；字形元数据或 A8 位图失败会置一次性故障 latch。STB 的活动边与 96 px 字形动态扫描线也在分配失败时返回，避免先解引用空指针。

5. 内存失败注入

主机测试使用真实补丁后 LVGL 9 源码和自定义分配器，保持 LV_USE_ASSERT_MALLOC=1。测试先探测每条路径的分配数量，再逐个注入一次失败，保证失败点随上游实现变化时仍完整覆盖。

路径覆盖内容结果
create字体描述符、字体对象和三类 cache 的部分初始化回滚全部失败点无断言、无泄漏
metadatacache entry、红黑树节点与链表节点失败锁存，后续字形请求停止
bitmap绘制描述符、A8 数据、STB 活动边和 96 px 动态扫描线缓冲释放，无空指针访问
repeat28/96 px 交替创建、取字形、绘制、释放和销毁 1,000 次live block/bytes 每轮回到稳定基线

当前矩阵共覆盖 25 个单点失败位置，并额外验证普通 draw buffer API 仍只在描述符失败时断言、像素缓冲失败仍返回空指针；字体可恢复路径结果为 oom=1、asserts=0。重复生命周期结束时 LVGL 全局稳定基线为 7 blocks / 3,056 B。该稳定基线不是板上字体内存预算。A1/B 仍需分别采集主堆和 PSRAM 字形池，并证明反复进出没有持续增长。

6. 主机验证

正式入口：

python -m pip install -r firmware/requirements.txt
python firmware/sdk_patch.py prepare --base-sdk <fixed-sdk> --output <derived-sdk> --init-submodules
.\firmware\tests\run-d07-a0-tests.ps1 -PythonPath <python.exe> -PatchedSdkPath <derived-sdk>

本轮通过固定 SDK 与派生 SDK 校验、两次字体生成、25 点 OOM 矩阵、1,000 次生命周期、25 项 Python 检查和两套真实归档解析。完整核心回归和 HTML 链接、锚点、校验和检查也必须在提交前通过。测试输出位于忽略入库的 firmware/tests/build/d07-a0/，不作为可烧录产物。

7. A1 准入门槛

  1. 在当前未替换字体的固件上采集五个规定视图，记录构建身份、亮度、照片和原始串口证据，并把基线 JSON 的状态改为已完成。
  2. A1 必须使用由补丁工具创建且验证通过的派生 SDK；不得直接修改固定 SDK。
  3. A1 只替换兼容子集并收紧 cache，保留七个旧字号；先完成主机和双工具链预算，再申请 G2 上板。
  4. 替换后逐条复验五组通知、简繁长文、滚动、按键返回和 20%/80% 亮度；任何缺字、布局变化、断言或重启都回滚。
  5. 主堆和 PSRAM 字形池分别记录峰值与稳态；除残留 ≤32 KiB 外，还必须证明多轮页面切换没有持续增长。
