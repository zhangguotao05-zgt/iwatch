所有权与接口

模块责任及边界
iw_scope页面令牌由 page_id 与单调 generation 组成。固定登记 8 个定时器、8 个动画、16 个回调/订阅、16 个句柄。登记失败不移交所有权；重复停止安全。
iw_routes按 ID 排序的只读注册表。包含所属 App、父页、能力、恢复方式、状态、参数、资源、参考 ID 和测试编号。尚未实现的页面明确标 RESERVED，参数和资源不伪造为可用；正式页面接入时补齐其具体契约。
iw_navigator只持有已提交意图、候选目标和最近访问摘要；不复制 SDK 运行栈。返回目标、实际深度和运行 App 数来自框架快照。
iw_routerGUI 线程中的适配器。串口仅投递有界请求并唤醒；页面创建、生命周期、输入取消、回收和 LVGL 操作全部在 app_watch 内完成。

页面暂停时保存滚动位置、暂停 scope 中的可见活动并取消输入。页面退出先使令牌失效，再注销回调/订阅，停止定时器及动画，释放句柄和项目对象。SDK 随后删除自己的屏幕；页面状态内存等这一轮框架调度返回后才释放。对象与字体回收须先确认 GPU/LCD 已空闲。

资源所有者登记上限从 D07 的 8 调整为 18：两个 App 各八页，另留两个全局使用方。登记是有界链表，不申请额外节点。没有引用的字体仍通过 D07 字体服务在安全点统一回收。

导航事务、容量与失败回退

  1. 检查当前实际页面、能力、参数、最多两个运行 App、单 App 八级深度。目标尚未实现、能力不可用或达到容量时保留当前页面；返回不因新发生的能力故障被禁止。
  2. 进入 PREPARING，准备页面状态和作用域。SDK 返回成功仅说明请求已入队，随后进入 TRANSITIONING。
  3. 收到目标 ONRESUME，同时确认实际框架完成转场并收敛后才 COMMITTED。事件先后次序不影响结果；重复事件和过期序列不重复提交。
  4. 在途普通导航返回 BUSY；返回独占一个待处理位，连续返回合并一次，在下一安全点执行。
  5. SDK 未受理或异步建页失败时 ABORTED，当前页和历史不提交。目标组件构造失败时通过 SDK 返回原页；全局字体故障按所有使用方清理后退回该 App 根页。
  6. 回退请求连续三次无法受理时停止自动重试，保留 SDK 对象所有权并显示应急层；KEY1 允许再发起恢复，不在回调内强删忙碌对象。

历史最多六个 App，每个只保留最近页面参数、滚动位置、选中项和不超过 64 B 的草稿；单份摘要编译期限制为不超过 128 B，不存 LVGL 指针。第七个 App 驱逐最旧条目。同一个 App 的子页跳转更新该 App 的摘要，不挤满六个槽。

缩略图是独立的可选资源句柄。获取失败仍提交图标 ID 和名称；替换、驱逐及清空历史释放原句柄。D08 目标没有安装缩略图生产者，始终提供图标/名称模型；D13 再接图像生产与切换器画面。主机验证的是生产者失败后的历史策略，不宣称开发板已执行图片分配耗尽。

受控 SDK 适配

基础 SDK 固定在 421126d9f476ed8e2a6f0b0ca28a9f241c182e65 并保持干净。派生补丁继续由 sdk_patch_manifest.json 管理，当前白名单 29 个文件；补丁及每个文件的 SHA-256 进入构建身份。D08 没有关闭全局断言或撤销字形缓存同步。

  • 新增公开只读页面快照和一次调度推进入口。项目不包含 gui_app_int.h，不访问私有页面链表或调用私有转场中止函数。
  • 消息分配/邮箱发送失败可返回错误，失败不改变输入开关，发送成功后移交消息所有权。
  • 框架在改变原页状态前准备新节点和屏幕；节点、样式、屏幕与屏幕表分配失败均回收新资源。深度和附加内存整数溢出在分配之前检查。
  • 屏幕采用固定样式，避开初始化主题的隐式分配；根屏幕坐标已经为零时，LVGL 切屏不再重复创建局部样式。主机曾捕获该处分配失败崩溃，现已纳入真实入口故障注入。
  • 框架生命周期处理前确认绘制资源空闲。跳过动画或无动画的路径用“真实栈已恢复且框架空闲”确认完成，不依赖不存在的动画完成回调。

诊断页固定使用无视觉转场动画和 Q0；SDK 暂停页面的流程仍可能申请快照缓冲，不能写成完全没有快照。现有其他页面的视觉动效没有扩展为可中断转场；D14 再验收这一能力。本轮主机的两个事件次序不等于实机已经测试任意动画中断。

显示异常排查（未关闭）

首次采集窗口中，用户报告未点击 Next 就已半黑半白，并自行复位。异常发现前最后可见的路由快照为 Main/n00000017、depth=2、seq=45；无法由现有串口记录还原异常开始的确切帧。复位前未记录到断言或 LCD 超时，但这不能证明显示链路正常。

用户复位后，从表盘单次打开 Page 1 显示正常；随后重新执行桌面 10 次进退、八级/第九级边界和 5 次在途返回，再打开 Page 1，用户确认画面正常。第二轮 recovery=0，GUI 栈峰值 31%、LCD 栈峰值 44%。尚未稳定复现，不能将第二轮正常写成修复通过；未据此修改屏幕参数、缓存同步或断言设置。

复现准备阶段，app_run Main 后主堆为 59,400 B，第一次进退降为 59,388 B，严格相等检查因此停止；该记录保留。再次从 59,388 B 开始的完整流程保持稳定，字形池均为 72 B。两组采样条件分开记录，不掩盖第一次检查结果。

用户推测可能是屏幕接触原因，但尚无验证支持该归因。其后手动 Next/KEY1、应急返回及两档亮度通知页复验均正常。本轮没有据此修改固件；“复位恢复”和“后续未复现”不等于根因修复。

问题记录为 logs/board-validation-20260917-d08-r2/display-incident.json，状态为未定位、后续未复现。原始日志已经封存，首次异常、采集缺口和用户反馈全部保留；封存摘要中的待审状态反映采集当时的结论，本节单独记录后续风险接受决定，不改写历史证据。异常已转入 显示异常 #10，保持未定位、后续未复现。如果再次出现，先保存画面、时间点和操作步骤，在复位之前采集路由、线程、输入和显示状态，再重新评估影响；不能因 D08 已收口而忽略。

边界与后续

本轮实现导航基础及诊断页，不代表正式七页界面已完成。全局双键/表冠语义在 D09，新版顶栏、七页布局、53 个新增字符在 D10。长文历史最大 215 ms 和溢出频率继续由 性能待办 #8 跟踪，不宣称全面性能达标。联网、持久化与自研板定版不在本轮范围。

D08 基础实现及已验证功能已按“接受已知风险”批准收口，允许开始 D09 输入开发；显示异常 #10 和性能遗留 #8 继续独立跟踪。本记录保留主机策略、真实目标构建和实际硬件证据的分别结论，不把阶段放行写成产品发布验收通过。
