D13-C 锁与输入仲裁实施记录

2026-09-21 · Issue #15 · D13-A 基线 c7617c2 · C 阶段首个增量 · 待架构复核

本页只记录普通输入锁和水锁的首个 C 阶段增量，不包含表盘编辑、会话草稿提交或 D15 持久化。实现先在主机完成状态、输入和资源回归，再完成 GCC/Keil 目标构建；本页不把主机构造测试当作实机故障注入，也不表示 D13 总体收口。#8 长文／输入性能、#10 显示异常和 D15 flash1 继续独立跟踪。

范围与验收契约

项目本轮行为明确边界
普通输入锁控制中心底部整行提供正式入口；能力可用时进入锁页，能力缺失时显示“未接入”并禁用。不是密码安全功能，不模拟摘腕、支付或防盗；C 阶段暂只支持 KEY1 长按解锁。
水锁控制中心水滴卡进入独立水锁页；触摸和 KEY2 在锁定期间不产生业务动作。水锁只屏蔽输入，不代表设备具备防水保证；提醒可以显示摘要，但不能取得触摸输入。
解锁规则KEY1 连续按下达到 2,000 ms 只进入“可解锁”状态；真实释放边沿才产生一次解锁信号。未达到阈值、短按、KEY2、重复释放均不解锁。长按期间不提前穿透；取消或切换上下文清理候选手势，并等待真实释放后再接受下一次按下。
返回规则解锁后恢复普通输入并关闭锁页覆盖链，返回进入锁页前的来源页；来源已失效时由路由器回到可用根页。锁页没有触摸命中区，不在绘制回调中直接改路由或删除页面。

实现结构

  • core/iw_keys 将水锁和普通输入锁统一为 IW_KEY_LOCK_WATER／IW_KEY_LOCK_INPUT 两种模式，共享有界的按键状态机；新增 unlock_ready 记录阈值已到但尚未释放。
  • platform/iw_key_port 在 GUI owner 线程切换输入上下文，提供按键能力自检和解锁进度查询；中断路径只复制边沿，不执行 LVGL 或路由操作。
  • platform/iw_router 在锁页恢复／停止时同步输入上下文；锁页按覆盖层处理，但路由描述仍标为可用页面，避免被通用导航能力检查误拒绝。
  • gui_core/iw_product_scene 绘制控制中心、普通输入锁页和水锁页。锁页仅有标题、锁图形、KEY1 说明和进度条，iw_product_scene_hit 不返回可点击动作。
  • gui_apps/watch_demo 在收到 GUI 线程中的解锁意图后先恢复普通输入，再通过 iw_router_home() 关闭锁页覆盖链；进度只更新当前可见锁页模型。
  • 正式字体清单加入本轮三条中文文案，生成子集与清单哈希同时更新，避免目标构建使用过期字体输入。
