当前通知页会创建 16、18、20、22、24、26、28 px 七种 tiny_ttf 字体，默认每种配置 128 个 glyph cache 和 256 个 kerning cache，且只以条目数限制，尚无字节级运行时预算。因此 D07-A 必须同时建立 Flash 预算和运行时高水位。

v1 的 215 字符样本没有覆盖现有通知区的 121 个唯一字符。v2 样本将这 121 个字符全部加入后共有 336 个唯一字符；源字体 SHA-256 为 05d71b179ef97b82cf1bb91cef290c600a510f77f39b4964359e3ef88378c79d，使用 FontTools 4.65.0、保留 hint，两次独立生成均为 56,804 B，SHA-256 均为 4f69f4ba565598e217501e7985bfdc7ccfd68d0bed472325218d01e89bbe284f。该样本只证明 128 KiB 可行，关闭任务仍以正式清单和最终产物为准。

3. 方案与阶段门槛

采用“内置兼容子集 TTF + 内置应急位图字体 + 图元优先 + 外部包延后”的方案 B。D07 分成两个不可跨越的门槛：

  1. 字体替换门槛：完成字符清单、双工具链分项计量、受控 SDK OOM 补丁、旧页面主机回归和开发板实屏回归。任何缺字、字号变化、断言、重启或预算超限都停止 D07。
  2. 组件开发门槛：字体替换门槛通过并保存构建与板测证据后，才允许实现统一字体服务、主题 token、共享组件和展示页。

D07-A 的首个可刷镜像只替换字体资源和必要的安全处理，不同时引入新组件，以便把旧页面退化与资源变更直接关联。

4. 分项容量预算

预算项阈值计量边界超限处理
subset_ttf_bytes≤131,072 B最终镜像中子集 TTF 的实际链接字节，不使用源文件大小代替。构建失败。
bitmap_font_bytes≤65,536 B最终镜像中实际链接的位图字体资产对象贡献；当前白名单为 lv_font_montserrat_*.o，共 51,335 B，不把字体引擎代码混入资源统计。构建失败。
image_bytes≤1,048,576 B实际链接的 .ROM3_IMG* 输入段，包含段头，不统计已被链接器回收的对象。构建失败。
main_bin_bytes≤4,194,304 B最终可烧录 main.bin 文件大小。不归档、不允许烧录。
font_runtime_peak_delta≤524,288 B从字体服务初始化前稳定基线到旧通知全量滚动或展示页最坏场景的最大堆增量，包含对象、三类缓存和 A8 字形缓冲。D07-A/D 不通过；先缩小按字号配置的缓存，再评审阈值。
font_runtime_idle_delta≤32,768 B页面销毁、字体引用归零并连续两轮稳定采样后的残留增量。视为泄漏或未释放引用。

运行时字体缓存不得继续无条件使用 128/256 的默认条目数。实施时使用显式按字号配置：正文 16–30 px 从每种 16 个 glyph/draw 条目起测，大字 64–96 px 从每种 4 个起测；kerning cache 从 32 个起测。最终值由旧页面滚动和最大字号实测决定，并写入构建配置与板测记录。

5. 旧页面兼容

字符输入采用受版本控制的白名单，不扫描注释或全部文档：

  • 可打印 ASCII 与明确列出的常用符号；
  • src/resource/strings/zh_cn.json 的全部值；
  • app_clock_status_bar.c 的 notify_msgs 十个现有标题和正文字符串，包括简体、繁体、数字和英文品牌名；
  • D07–D10 的静态产品文案清单。

生成器输出 manifest，记录每个输入文件 SHA-256、源字体 SHA-256、FontTools 版本、码点列表、输出大小与哈希。测试直接读取上述白名单来源并验证每个码点都存在于子集 cmap；同时按码点比较源字体与子集的 advance、边界和垂直度量。新增或修改文案却未更新清单，或旧字符度量发生变化时，构建失败。

D07-A 原样保留现有 16、18、20、22、24、26、28 px，不修改通知区尺寸、换行或滚动行为。D07-B 的字体注册表显式支持旧字号与新 token 的并集：16、18、20、22、24、26、28、30、64、80、96，共 11 种；替换现有 MAX_FONTS 10 的隐式限制。字体按 GUI owner 中的 acquire/release 引用管理，引用非零时不得销毁或淘汰。

16、18、24、28 px 标记为 legacy，只供现有页面使用；新组件不得引用。后续逐页迁移必须单独提交，并通过文字边界、换行、滚动和实屏前后对比后才能删除对应字号，D07 不以强行合并字号换取容量。

6. 双工具链计量

两套工具链输出同一结构的 resource_budget.json，至少包含工具链、仓库 HEAD、SDK 基线与补丁哈希、main/font/bitmap/image 字节数、阈值、证据文件哈希和判定。报告纳入 build_identity.json 的 artifacts，修改 map、ELF/AXF、main.bin 或预算报告都会使身份复核失败。

工具链TTF 与图片位图字体一致性检查
GCC从最终 ELF 节表统计唯一 .font_data 和所有 .ROM3_IMG*；拒绝缺节、重复 TTF 节和越界节。从 GCC map 的已分配输入段汇总位图字体资产白名单 lv_font_montserrat_*.o，忽略地址为零的已回收段。ELF 段总量、map 输入贡献、main.bin 和现有布局检查同时成立。
KeilAXF 只用于身份和地址复核；容量从同一归档 map 的 DroidSansFallback.o(.font_data)、DroidSansFallback 符号及 .ROM3_IMG* 输入段统计。从 map 的 Image component sizes 与已分配输入段交叉核对位图字体资产白名单 lv_font_montserrat_*.o 的 RO Data。map 必须识别为 armlink，且 map、AXF、main.bin 哈希属于同一次构建；符号与输入段不一致立即失败。

解析器使用合成 GCC/Keil 样本覆盖恰好等于阈值、超限 1 B、缺失、重复、未分配段、截断 map、错误工具链和陈旧 map，再对当前两套真实归档做回归。不能用 GCC 规则推断 Keil，也不能用源 TTF 文件大小代替链接结果。

7. 字体内存失败处理

现有 iw_recovery 在普通页面前创建，使用内置 lv_font_montserrat_20 和静态英文文本；show 只切换预先存在对象的可见性，不创建控件、不替换文本。字体服务初始化失败或绘制失败时只显示该应急层，不在低内存路径再次申请中文字体。

固定 SDK 当前启用 LV_USE_ASSERT_MALLOC=1，断言处理为 RT_ASSERT(0)。tiny_ttf 的 cache、红黑树节点和 draw buffer 描述符分配在空指针检查前包含断言，且 cache 部分创建后缺少统一回滚。D07-A 不关闭全局内存断言，而是加入最小、可审计的 SDK 补丁：

  • 只在补丁白名单内把预期可恢复的字体分配改为立即判空并返回，避免空指针先进入致命 LV_ASSERT_MALLOC；其他参数、状态和内存完整性断言保持启用；
  • tiny_ttf 三类 cache 初始化改为返回结果，任一步失败都逆序释放已有 cache、字体描述符和字体对象；destroy 接受部分初始化状态；
  • glyph cache entry、红黑树节点、draw buffer 描述符或 A8 数据失败时返回无字形，并触发只写的字体故障 latch；
  • 故障 hook 只在 GUI owner 中增加饱和计数并置 latch，不调用 LVGL、不打印长日志、不重试；GUI 主循环在当前绘制/事件分发结束后取消页面输入、销毁失败页面并显示预创建应急层；
  • 故障分为 create、glyph metadata、glyph bitmap、fallback shown 四类计数，避免把缺字与内存不足混为一类。

补丁保存在仓库的版本化目录，记录适用 SDK 基线 421126d9f476ed8e2a6f0b0ca28a9f241c182e65、允许修改的文件和 patch SHA-256。构建包装脚本从干净锁定 SDK 创建隔离的派生 worktree，先 git apply --check，再应用补丁并验证差异白名单；固定 SDK 本体保持干净。GCC 与 Keil 必须使用同一派生源码，构建身份同时记录 SDK 基线、补丁哈希和补丁后文件哈希。任何手工 SDK 修改都拒绝构建。

故障注入覆盖字体描述符、字体对象、三类 cache、cache entry、红黑树节点、draw buffer 描述符和 A8 数据；每个点验证无断言、无重启、无泄漏、应急层可见且表冠/按键仍可返回。绘制期间失败还要验证不会在 LVGL 回调内删除对象，也不会每帧重复重试。

8. 外部资源包边界

D07 只冻结接口，不读取 NAND/NOR。公共资源包使用 64 B 小端固定头：magic[4]、schema_version:u16、header_bytes:u16、resource_version:u32、compatible_api:u32、payload_bytes:u32、entry_count:u32、payload_sha256[32]、flags:u32、header_crc32:u32；magic 为 IWR1。

资源 ID 由注册表显式分配，不使用运行时路径哈希。D15 再确定 TOC、A/B 提交、ECC/坏块、签名和流式解码。D07 的 Provider 只有内置 R0 与 UNAVAILABLE 两种真实状态，不能因分区表存在 FS_REGION 就报告外部资源可用。

9. 主题与组件架构

模块职责禁止项
gui_core/iw_theme提供 390×450 profile、颜色、间距、圆角、字号、动效和 Q0/Q1 token；数据只读。不访问服务、不创建对象、不分配堆。
gui_core/iw_fontGUI owner 管理 11 个显式字号、引用、按字号 cache 配置、故障 latch 和计数。组件不得直接创建、销毁或调整 tiny_ttf。
gui_core/iw_components创建和更新无业务状态的原子组件；父对象拥有子树，状态通过显式模型更新。不订阅服务、不创建业务 timer、不保存调用方临时字符串指针。
gui_apps/component_gallery展示全部状态、最长中文、最大字号、Q0/Q1 与降级；只作开发入口。不加入产品桌面，不承担 D08 路由。

首批组件保持为 ScreenFrame、ListRow、PillButton、StatePanel、StatusBanner。构造返回明确错误码；中途失败逆序删除已创建对象并清空句柄；重复 destroy 安全。事件只上报语义动作，由页面 Presenter 决定是否提交服务命令。

10. 实施顺序

  1. D07-A0 · 工具与安全链：先保存当前通知页七个字号、五组文案的主机/实屏基线，再完成正式字符清单、确定性子集生成、GCC/Keil 分项预算器、SDK 补丁管理和主机故障注入。此阶段不改变可刷镜像。
  2. D07-A1 · 兼容字体替换：只切换到兼容子集并收紧 cache 配置；保留七个旧字号；完成双工具链构建、预算、旧页面主机回归和开发板实屏回归。
  3. 门槛 A：D07-A1 通过且证据归档后，才允许继续；否则回滚字体替换，不开发组件。
  4. D07-B · 字体服务与主题：实现 11 个显式字号的 acquire/release、只读主题 token、运行时高水位和应急层衔接。
  5. D07-C · 首批组件：实现五类无业务共享组件，不接业务服务。
  6. D07-D · 展示与验收：建立组件展示页，完成生命周期、OOM、双工具链和开发板验收后关闭 Issue #7。

每阶段单独提交。任何固件变化都重新生成 GCC/Keil 归档；只有通过 G2 且完成身份复核的 GCC 三件套允许写入开发板。

11. 验收矩阵

字符与生成两次生成、输入漂移、缺字、121 个旧通知增量字符、全部 10 条现有通知字符串及逐码点度量比较。哈希可复现；旧文案无缺字，advance、边界和垂直度量不退化。

组件 T12中英文、大字、最长文案、按下、等待、禁用、空态、错误态、Q0/Q1。无重叠、越界或不可读；占位不改变交互区域。
组件生命周期五类组件各 1000 次创建/销毁、逐分配点 OOM、重复 destroy。无泄漏、释放后访问、悬空回调或 timer。

12. 非范围

  • D07 不写 NAND/NOR、不挂载 flash1、不实现资源包 A/B，也不声明断电保存；这些属于 D15。
  • D07 不实现真实屏幕故障的确认、有限重试、分项恢复计数或受控重启；这些属于 D16。
  • D07 不实现页面注册表、返回栈和导航事务；这些属于 D08。
  • D07 不完成正式设置、亮度和手动校时页面；这些属于 D10。
  • D07 不复制 Apple 字体、图标或受限资源；所有资源必须记录来源与许可。
