D14 蜂窝桌面与转场实施记录

2026-09-22 · D14-A0 目标构建通过 · D13-D 已获架构复核并已推送 main · Issue #15 保持打开

本批先落地可验收的蜂窝桌面闭环，不把旧示例菜单或静态图片当作产品功能。主机测试、目标构建和开发板实测分开记录；目标构建已完成，开发板尚未刷板。

产品目标

在 390×450 的离线 UI 上提供 Apple Watch 风格的蜂窝入口：应用列表右上角进入蜂窝桌面，蜂窝桌面只展示已有真实页面的固定注册项，点击磁贴进入对应业务页，返回回到蜂窝桌面，再返回列表。未实现的健康、联网和系统能力继续保持 RESERVED，不显示成可用 App。

本批完成条件

  1. 蜂窝页面使用固定坐标和固定节点，不为每个磁贴分配长期对象或图片缓存。
  2. 磁贴的显示区域与命中区域使用同一坐标，点击设置、计时器、秒表、闹钟分别进入其 READY 根页。
  3. 蜂窝页的 Back 回到应用列表；列表入口不会改变现有业务清单和返回语义。
  4. 转场继续复用现有路由事务、字体 owner、输入取消和安全点回收；构造失败时由既有恢复层接管。

蜂窝桌面契约

状态行为失败处理
应用列表右上角点阵图标进入蜂窝页，列表中的真实应用顺序和数据不改变。路由忙、能力不足或页面创建失败时留在列表，沿用现有错误和恢复层。
蜂窝正常显示四个 READY 根页磁贴：设置、计时器、秒表、闹钟；点按磁贴进入对应页面。目标能力在提交前由路由重新校验，失败留在蜂窝页并显示已有不可用结果。
蜂窝返回Back 返回应用列表；从业务页按既有 Home/Back 契约返回，不改变最近 App 账本。来源页已销毁时由路由恢复到应用列表或应急层，不保留悬空页面指针。
资源不足不增加全屏图片和动态缓存；字体、节点和对象仍由现有 owner 管理。页面构造失败进入既有 UI unavailable/恢复路径，不伪造半成品磁贴。

实现范围

文件改动
src/gui_core/iw_routes.c将 LAUNCHER_GRID 从旧 LEGACY 描述提升为 READY，并挂在应用列表下。
src/gui_core/iw_product_scene.[ch]增加蜂窝磁贴布局、列表入口动作、固定节点边界和稳定目标页面 ID。
src/gui_core/iw_product_view.c增加无图片资源的 3×3 点阵入口图标，并沿用统一绘制故障保护。
src/platform/iw_product_controller.c处理列表到蜂窝桌面的明确动作，目标页仍由统一路由事务创建。
tests/d07_tiny_ttf_oom/test_product_view.c把蜂窝页加入页面矩阵，验证首个磁贴的显示命中和设置页动作。

本批没有接入旧的 app_mainmenu.c 示例，也没有复制另一套 App 注册表。蜂窝页使用现有路由表中的 READY 页面，避免列表、蜂窝和最近 App 的身份分裂。

明确边界

  • 当前四个磁贴只代表已有 READY 页面；健康、运动、联网、钱包和媒体等 RESERVED/E 能力不显示为可用。
  • 蜂窝图标是项目自绘点阵，不使用 Apple 专有图标或资源；视觉仍需按 390×450 参考稿和实屏结果继续调整。
  • 列表/蜂窝切换、拖拽排序、徽标、程序坞和复杂表盘预览不在 A0 首批收口，分别进入后续 D14 增量。
  • #8 长文输入性能、#10 显示异常、D13-C 水锁实体触摸和 D15 持久化继续独立跟踪。
