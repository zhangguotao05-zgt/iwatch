两类缺陷及修复边界

现象证据与原因处理
进入表盘时停机rt_free 检出重复释放；主机长通知字距缓存淘汰在 ASan 下复现。be31c1b 关闭字距缓存。后续原始日志记录两次正常进入，没有再次断言；这不代表文字显示通过。
中文笔画错乱，部分标题正常TinyTTF 在 PSRAM 生成 A8 像素，字体 handler 没有 flush 回调；EPIC 标签层未设置 data_size。首次混合按几何尺寸清理缓存，后续混合按 0 B 清理，GPU 可读到旧内容。39c8607 将标签前景层长度设置为 mask_stride * glyph_height，覆盖行填充。保持原有 GPU、缓存容量及页面行为。

渲染修复纳入原受控 SDK 补丁，白名单由 11 个文件扩展为 12 个，新增 middleware/lvgl/lv_drivers_v9/sifli/lv_draw_epic_label.c。固定 SDK 保持干净；派生 SDK、补丁文件及文件哈希均由构建身份验证。

主机验证方法与结果

原淘汰测试只查询字形描述，没有验证像素。本轮补上缓存字形与无缓存重新光栅化的逐行比较，并直接编译生产 _draw_epic_letter 及 drv_epic_cont_blend，仅替换硬件边界。测试模型维护独立的 CPU/GPU 像素视图，按生产代码实际请求的清理范围同步。

对照结果
修复前，2 轮全部旧通知与 7 种字号4,046 次提交，4,045 次 GPU 像素不一致；首个提交一致。缓存与重新光栅化的像素比较通过。
只补齐前景字形长度后4,046 次提交，0 次像素不一致；主堆分配计数回到初始值，无 OOM 或断言。
内存安全22 个分配失败点、1000 次创建销毁、10 轮长通知描述淘汰通过。ASan 同时覆盖 LVGL 库和测试代码。
目标一致性主机启用与目标相同的 LV_TINY_TTF_FILE_SUPPORT=1，使用内存数据源的 stream 路径。

主机模型验证缓存范围和像素契约，不模拟真实 EPIC 寄存器、总线时序及 OLED。修复前后完整输出位于本地 logs/d07-pixels-before-fix.log、logs/d07-pixels-after-fix.log。复现入口为 firmware/tests/run-d07-a0-tests.ps1。

实机复验与剩余门槛

前一候选 be31c1b 的原始串口位于 logs/board-validation-20260917-d07-a1-fixed/com10-coldboot.bin；文件名沿用采集命名，用户确认的是取下跳帽后复位，不能据此增加一次断电冷启动结论。CO5300 ID 0x331100、FT6146 0x64/0x56 及 GUI 启动均有日志。

缺陷状态下已记录：字体进入 2 次、存活 7 个；create/metadata/bitmap/fallback 均为 0；主堆峰值 113,612 B，PSRAM 字形池峰值 35,524 B；9 个按键输入中最大延迟 117 ms、1 个 ≥100 ms 样本。这些只属于失败候选的诊断证据，不能写成新修复通过。

新镜像实机状态：待烧录复验。需验证首次进入、全部中文通知滚动、反复进出后的文字完整性和按键触摸响应；同时记录亮度 20/80、两类堆的连续样本、线程栈及输入延迟。观察确认不要求新增照片。A1 实屏及资源门槛通过后再推进新组件。
