原因与最小修改

旧工程在 configure 时用 file(READ) 读取生产／SDK 文件并写出 inc，但未登记原文件的 CMAKE_CONFIGURE_DEPENDS。原文件变化不会自动重新运行抽取；inc 到对象的 OBJECT_DEPENDS 不能弥补前半段缺失。

d07_tiny_ttf_oom 增加 iw_track_extracted_source，将路径归一为 REALPATH 后登记目录配置依赖，覆盖 8 个直接读取路径及 extract_sdk_function 的全部来源。control_router 复用该助手，覆盖 extract_function 和 IW_ROUTER_SOURCE。原有 inc 到 router_model 对象的 OBJECT_DEPENDS 原样保留；未改变抽取算法、编译选项或目标 ABI。

首次直接登记未经归一的路径时，父子目录通过不同 ../ 形式指向 watch_demo.c，Ninja 报重复输出；该失败记录保留。REALPATH 消除路径别名后，默认和覆盖来源均通过。
