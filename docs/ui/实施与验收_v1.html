iwatch 架构实施与验收 v1

日期：2026-09-16。架构见 系统架构，视觉标准见 视觉与交互规范。本表控制执行顺序，不代替完整界面覆盖清单。

v1.1 复审后增加 M0.1，拆细 M1，并将其所需时间与服务基础前移。逐项工作见 D01–D18 开发任务，边界用例见 T01–T25 测试矩阵。T01–T04 及 T05 的单键部分已有 D01–D03 主机和板上结果；T06、T08、T09 与 T10 的纯模型部分已在 D04/D05 主机通过，T07 的校时、软件复位保持和无备份掉主电已完成板测。

2. 第一批代码范围

以下保留 M0 基础批次的范围，实际完成状态见第 6 节。D01–D03 已完成，D04/D05 状态见第 7 节：

  • 构建前检查本板 PSRAM/NAND 区域的容量和重叠；构建后检查实际装载镜像大小。
  • PSRAM1 数据区由 12 MiB 修正为 10 MiB；main 装载槽改为 NAND 偏移 16 MiB、容量 6 MiB，保持已有 NAND 数据分区地址不变。新槽与启动表的实物验证单独执行。
  • 用固定容量队列把按键事件交给 GUI 线程；软定时回调不再操作 LVGL，也不同时读写未保护的按键状态。
  • GUI 按有限批次消费事件；溢出时取消当前输入序列并等待释放，提供入队/消费/丢弃/峰值深度诊断。
  • 保留现有单击 Home 行为；单/双击语义和新系统页面在 M1 一起接入，以免只有识别事件却没有对应界面。

第一批没有修改 LCD 或 FT6146 的硬件协议；为解决实测栈超限，项目本地化了 SDK 触摸读取线程并将栈固定为 2 KiB。新布局已在备份旧 FTab、NOR 和 NAND 后烧入，main 与 FTab 完成独立回读和冷启动验证。视觉状态仍是演示基线。

4. 性能记录规则

  • 保存构建 ID、编译器、SDK 版本、板型、显示配置、资源清单、采集日期。
  • 触摸反馈目标 P95 < 100 ms；导航从语义确认到首个新画面目标 < 100 ms，常用转场约 220–320 ms。双击窗口另计。
  • 使用输入时刻、GUI 消费、渲染提交和驱动 flush 完成四个时间点；显示完成与真正肉眼出现仍有差别，必要时高速录像复核。
  • 帧率记录场景、窗口、平均值、P95/P99 帧间隔和最长停顿；30 fps 基线不能只用平均值掩盖明显卡顿。
  • 内存记录总量、当前、峰值、最大空闲块和页面退出后稳定值；同一缓存热态比较。
  • 所有阈值均是验收目标，当前尚没有长期测试和新系统界面帧率的通过结果。

5. 设计变更规则

改变板型、电源、分区、线程所有权或资源上限，先修改架构与对应检查。普通页面的颜色和间距在主题令牌中修改。新增 App 先登记页面契约、依赖能力和预算，再写页面。

仍待确认的事项：watchOS 26 的参考小版本/地区；实际表冠与侧键；FT6146 完整坐标和方向；NAND FAL 与提交语义；新界面实屏性能。均有对应阶段，不阻止先完成架构和离线基础。
