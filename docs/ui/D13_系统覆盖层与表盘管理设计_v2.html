2026-09-20 · Issue #15 · D13-A 重新申请架构复核 · 仅设计，不是功能验收

D12 审批基线 62f0686、固件源码 9fa21c8 保持不变。本版修正 v1 的输入优先级和 Home 口径，恢复 32 条普通通知的独立契约，并冻结覆盖层、历史、表盘与 390×450 视觉目标。针对 v2 复核，再补齐覆盖层转业务页的事务及 Back 落点、控制中心普通锁产品入口。在 v2 获批前不进入 D13-B；本版没有修改固件、目标构建或开发板。

输入仲裁、普通锁与水锁

D09 的语义识别器先处理原始按下／释放，再由当前 GUI 上下文唯一消费。输入优先级严格为应急恢复、IW_INPUT_WATER、IW_INPUT_LOCKED、IW_INPUT_ALERT、IW_INPUT_OVERLAY、页面编辑／滚动、NORMAL 全局。画面 Z 序与输入所有权分开：关键提醒可以显示在锁页上方，但锁定时只显示不含敏感详情的“有待处理提醒”；提醒按钮和触摸仍不可用，解锁后才重新读取 D12 快照并显示可操作内容。不能因提醒出现而切换到 ALERT 输入上下文。

水锁沿用 D09 KEY1（开发板的表冠按压替代）连续按住 2,000 ms 解锁。普通输入锁也选 KEY1 连续按住至少 2,000 ms、松开后才解除；两者由上下文区分，KEY1 长按只产生一次 UNLOCK，不补发单击／Home，KEY2、旋转与触摸均不得解锁。达到阈值仅显示进度完成，释放前仍保持锁定。锁定前已按下的键和触点全部取消；解锁后等真实物理释放与下一次完整新触点，禁止跨页残留手势。普通锁只防误触，不宣称密码保护、摘腕检测或持久锁定。

进入锁页采用 GUI owner 的事务：确认 KEY1 可读且退出路径有效 → 取消现有输入 → 创建并首次绘制锁页 → 切换输入上下文。创建／绘制失败则保留原页和原上下文，锁入口显示不可用。锁页存活中发生字体 OOM、页面故障或显示恢复失败时，停止计时器与回调、取消输入、撤销锁上下文，再由预创建应急层接管；应急层 KEY1 单击回应用列表。重启后会话锁状态清零。显示恢复成功但锁页仍有效时重绘锁页、保持锁上下文；不可确认时进入应急层，不显示未锁定的旧页面。GPIO 卡死或 KEY1 缺失时禁止开启锁；硬件 RESET 是最后的物理退出，不冒称软件可解开损坏按键。

当前 iw_keys_intent() 对 IW_INPUT_LOCKED 固定返回 NONE；识别器也只有 water_lock 模式才采用 2,000 ms 阈值，并在达到阈值时、尚未松手就发出 IW_KEY_UNLOCK。因此 C 阶段必须一并修改识别器的锁模式与边沿状态：达到阈值只置待确认，释放边沿才输出一次 UNLOCK；在释放前取消、页面故障或再次切上下文都清除候选。普通锁和水锁共用时长与释放门控，但分别保留上下文；更新既有 D09 水锁主机及实机回归，不能只改 IW_INPUT_LOCKED → NONE 的意图映射。输入上下文和可见页面须在同一 GUI 安全点提交。D09 已批准的触摸溢出取消、短临界区、GUI 独占 LVGL 与恢复优先级继续有效；v2 不把尚未修改的代码说成已支持。

普通输入锁的产品入口固定为控制中心底部整行“输入锁”，见控制中心稿。D13-B 尚无锁页和可靠的松手解锁时，该行显示“未接入”且禁用，不能通过串口诊断入口替代产品入口；D13-C 完成 KEY1 可读／退出路径自检、故障回退和输入回归后才启用。点击时仍按上一段的 GUI 事务处理：成功关闭控制中心并进入锁页，解锁后返回进入控制中心前按值记录的来源 B；准备或首次绘制失败则保留控制中心、其滚动位置及原输入上下文，并显示不可用原因。来源已失效时按表盘→应用列表→应急层回退。

覆盖层状态与 Home／Back 表

普通覆盖层记录按值复制的来源 {app_id,page_id,argument,generation}，不保存其他页的 LVGL 指针。普通链最多两层：第一层只能是控制中心、通知列表、智能叠放、切换器或表盘选择；第二层只能是通知详情或表盘编辑。控制中心进入水锁不占普通第二层。相同打开请求合并；不同第一层请求在链未关闭时返回 BUSY，不隐式换页。已有 D08 的 8 级页面栈是上限，D13 不能另造可突破它的栈。

普通覆盖层转业务页

点击先在 GUI 线程复制来源 B、覆盖层滚动／选中项及目标参数，校验目标路由 READY、能力和实体 ID；在途重复点击合并，其他跳转返回 BUSY。目标页面已恢复且路由快照确认后，才提交一次历史与返回锚点，在绘制安全点关闭整个普通覆盖链。目标创建、恢复、内存分配或确认超时失败时撤销候选路由，不写历史、不释放原覆盖层，保留原滚动与选择并显示错误；若回滚本身失败则进入预创建应急层。返回锚点是按值复制的来源，不保存旧页面指针；失效时依次落到表盘、应用列表、应急层。成功后的 Back 永不重开已结束的覆盖层。

普通通知与关键提醒的独立账本

B 阶段实现容量固定为 32 的 RAM 普通通知存储：稳定非零 ID、递增 revision／接收序号、来源类型、到达时间有效性、未读／已读状态及至多 256 B（含结尾零）的 UTF-8 文本槽。创建或复制只在完整码点边界截断；没有可靠 RTC 时显示“时间未校准”，不伪造接收时刻。插入、标记已读与删除均以 ID＋revision 校验，失败无副作用；序号饱和拒绝新项，不静默回绕。打开详情成功才标记已读，列表滚动和覆盖层退出不标记；删除只作用于普通通知。

容量满时先淘汰最早已读，若均未读再淘汰最早普通通知，并累加饱和淘汰计数；删除／淘汰后的旧 ID 选择返回“已变化”并安全退回列表。普通通知的数据源首期仅有具名本机生产者或明确的诊断注入；无生产者时显示“暂无通知”，不生成假来信、付款或联网消息。诊断项在页面标“本机测试”。32×256 B 文本为 8,192 B；元数据目标不超过 2,048 B，整个固定存储目标 ≤12 KiB，B 阶段用 sizeof 与 map 核对。

D12 的 24 槽关键提醒继续独立拥有 source／entity／occurrence／presentation_epoch 与 ACK／稍后语义。通知中心可投影其未确认摘要，但不复制进普通 32 槽、不参与普通已读／删除／淘汰；点击关键项转 D12 提醒详情并重新读取快照。普通通知删除不能清除闹钟；关键提醒隐藏不能标记普通通知已读。视觉列表“待处理提醒”和“普通通知”分组；两者都空显示单一空态。原总契约的双类容量保持不变。

切换器的历史写入与失效恢复

现有 iw_navigator.c 只在导航事务 commit() 中保存 leaving；iw_router.c 的 Home 直接调用 SiFli gui_app_run()／gui_app_goback_to_page()，没有同等历史写入。B 阶段将“可计入历史的前台离开”集中到一个提交 helper：跨 App 成功切换、从 App 成功 Home 到根页、从 App 打开切换器才提升最近项；同一 App 内子页切换只更新该 App 的最近可恢复摘要，普通控制中心／通知／叠放和提醒插入不改最近顺序。

Home 请求时在 GUI 线程从稳定快照复制 leaving 的 App ID、页 ID、按值参数、滚动和所需实体 ID 到待提交结构；只有目标根页 resumed 且真实快照确认后才写 6 项历史，重复 Home 与重试只写一次。失败／取消丢弃待提交值。过滤 SYSTEM 根页、控制中心、提醒、锁页、表盘选择／编辑、DIAGNOSTICS、不可用或未注册 App；表盘和应用列表不占历史。按 App ID 去重并移到最近端，满 6 项淘汰最旧并释放其缩略图句柄。首个必须通过的例子是“进入秒表 → Home 回应用列表 → 打开切换器 → 秒表可见”。

选择历史项时先校验 App 可运行、route READY、所需能力和实体仍存在；详情失效则退回该 App 已注册首页，首页也失效则移除该项并留在切换器显示“应用不可用”。运行对象被 SDK 回收时从值类型摘要重建，不持有旧页面指针。关闭卡片只移除历史和预览，不停止计时器／闹钟服务。最多保留 6 项，每次仅创建屏幕当前可见的至多 3 个卡片对象；快照获取失败时用图标＋名称，不占用全屏 RGB565 缓冲。

表盘 ID、可编辑字段与原子切换

表盘页面仍使用现有 IW_PAGE_FACE 路由，内部配置有稳定 ID：FACE_DIGITAL=1、FACE_MODULAR_LOCAL=2；不以数组下标或显示名称作身份。会话配置由 GUI owner 的 iw_face_session 值类型模型独占，包含 schema=1、active_face_id、revision、配色枚举（蓝／绿／橙）及模块表盘的中心槽（无／活动计时器／下次闹钟）、左下入口（无／设置／显示）、右下入口（无／关于）。数字表盘只消费配色；未选或缺失数据按既有数字表盘与明确空态回退。所有值限定枚举和能力，运行时从 D04／D11／D12 快照取真实数据，不把设计稿的固定样例写进服务。

选择／编辑页先复制当前配置及 expected_revision 为草稿；预览只读草稿。取消、Back、Home 或页面创建失败都丢弃草稿，当前表盘不变。确认时先检查 revision／ID／能力，再创建候选根对象并用当前同一时钟快照完成首帧；候选创建、字体、绘制或路由提交任一步失败即安全回收候选并保留原根与原配置。只有候选可显示且 GUI 安全点确认后才发布新会话配置、递增 revision、交换可见根；旧根待 GPU／LCD 空闲后释放。revision 饱和拒绝确认且无副作用。无持久化回执，不显示“已保存到设备”；重启回内置数字表盘默认配置。

表盘选择最多同时显示 3 张候选卡：中央 1 张使用真实项目表盘预览对象，两侧至多 2 张使用图元／名称，不生成离屏位图。切换瞬间最多 2 棵表盘根对象（旧＋候选）、1 个选择器根对象；编辑页与选择器共享预览，不额外复制整屏。新增目标峰值以同一根页、相同字体预热状态为基线：主堆 ≤32 KiB、PSRAM 字形池 ≤64 KiB；32 次进入／取消／确认后无持续增长。此为 D13 设计上限，尚非板上实测；B/C 如超限先削减预览或回 A 复核，不扩 D07 全局预算。禁止为单张 390×450 RGB565 预览额外分配 351,000 B 全屏缓冲；最多 48 个选择器／候选新增 LVGL 对象，C 阶段用故障注入与实机峰值核对。

视觉冻结与现有资源预算

D13 页面视觉目标给出九张真实 390×450 坐标稿、字号、独立命中区、正常／空／不可用／提醒插入／放大状态和与现有 Apple Watch 公开参考的差异。它沿用 D10 IW-VISUAL-2.0 的黑底、DroidSansFallback Regular、30／26／22／20 px 字级、56×56 最小独立命中区及 Q0/Q1。设计图不是原厂截图，也不是固件运行帧；开发时以同源主机渲染、目标固件实屏和参考图三方对照。

入口与返回增量用例

用例操作与故障注入必须观测
D13-B-01从表盘和设置子页各打开控制中心，再点显示设置；进入亮度详情并逐层 Back；另注入目标创建 OOM。成功链为亮度详情→显示设置→原来源；覆盖层已销毁且历史只提交一次。OOM 后仍在原控制中心及亮度位置。
D13-B-02叠放点活动计时器卡，Back 两次；点击前取消该 timer_id，再点原卡。成功链为计时器详情→列表→来源；过期 ID 保留叠放与卡片位置，不打开另一计时器。
D13-B-03叠放点下次闹钟卡，打开编辑后逐层 Back；点击前禁用最后一条闹钟。成功链为编辑→列表→来源；无有效闹钟时保留叠放，错误可见。
D13-B-04首次秒表 Home 后由切换器恢复；分别令历史详情和 App 首页失效。成功打开最近 App，Back 按其父级；详情失效降至 App 首页，首页失效留切换器并移除／禁用卡片。
D13-B-05以上每条路径重复点击、注入确认超时／OOM、提醒插入、来源 generation 失效。无双历史、双根或覆盖深度溢出；失败保持覆盖层选中位置，成功不返回已结束的覆盖层，来源失效按三级回退。
D13-C-01B 阶段尝试点击“输入锁”；C 阶段分别注入 KEY1 缺失、锁页首绘失败、正常进入后短按及长按松手。B 不进入锁页；C 入锁失败保留控制中心，成功后输入锁独占输入，只有满 2 秒真实松手才回原来源。
