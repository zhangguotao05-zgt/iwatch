D12 闹钟与全局提醒实施记录

2026-09-20 · Issue #14 · M2 · T18/T19 · 待架构复核

范围

D12 在 D11 单调计时基础上增加 16 个会话内闹钟、8 个计时器加 16 个闹钟的独立提醒槽、精确发生确认与九分钟稍后提醒。应用列表增加闹钟入口；提醒可从当前页面自动打开，Home 或返回仅隐藏画面，不确认提醒，应用列表保留重进入口。

开发板尚无已验收的马达或扬声器驱动。服务将 SOUND、HAPTIC 标为缺失，只启用视觉提醒。输出仲裁模型覆盖单一活动源与 30 秒上限，但实机不会声称已发声或振动。闹钟和提醒目前在 RAM 中，断电保持待 D15 存储修复后处理；flash1 的既有 FAL 报错不由 D12 掩盖。

所有权与关键路径

模块职责边界
core/iw_alarms固定容量闹钟、下一次到期、本地日期高水位与错过计数。无可信 RTC 时不响；校时或时区变化只重新计算未来到期，不连发历史事件。
core/iw_alerts24 个按源分区的提醒槽，同一源的新发生合并、旧 occurrence 拒绝确认。8 个计时器与 16 个闹钟同到期仍各占一槽；账本不依赖页面生命周期。
core/iw_alert_output按稳定顺序选择一个活动源，限制最长输出时间。硬件能力缺失时仅视觉；自动停声和隐藏页面都不等于 ACK。
services/iw_service草稿句柄、命令结果、闹钟及提醒快照；单线程推进业务。草稿复制进服务固定池，命令不保存 GUI 指针；ACK 与稍后提醒按源、ID、occurrence 精确匹配。
gui_core/platform闹钟列表／编辑、全局提醒页、自动打开及隐藏后的重进。只在 app_watch 线程创建或销毁 LVGL 对象，服务快照在模型锁内有界复制。

诊断命令 iw_alarm_add_diag、iw_alarm_delete_diag、iw_alert_stat、iw_alert_diag 和 iw_d12_result 可从 COM10 读取模型及 ACK 结果。串口入队成功仅表示受理，必须结合终态结果和快照判定业务结果。

三项状态整改与复验 · 2026-09-20

整改固件源码提交为 9fa21c86800ffabaf802cf2b2f1757102f28e4f7。稍后提醒再次到期时增加展示轮次，路由只隐藏旧轮次，使同一 occurrence 可以自动重新打开，同时仍按精确 ID 和 occurrence 处理确认。计时器提醒确认后，将摘要写入独立的 8 条历史环并释放活动槽。闹钟由用户禁用时撤销稍后期限，待确认记录进入 HELD 状态，既不自动响也不被当作 ACK，之后仍可明确确认。

主机回归包含架构复现的计时器和闹钟稍后重开、8 次确认后再创建、禁用闹钟保留待确认记录；四项独立复现均通过。正式核心回归和 GUI 生命周期、故障注入通过；Python 检查 46 项通过，字体重复生成检查因本机缺少 FontTools 跳过。GCC 和 Keil 从同一源码提交分别构建，归档文件哈希复核均无差异，map 工具链标记分别为 gcc、keil。GCC main.bin 为 1,935,980 B、SHA-256 e6111beffc3205650fcf72dee8b8ea61122535aedd911a94fa894d9575f641ce；Keil 为 1,860,808 B、SHA-256 206d29870c89829a145acea8a2a9000c50dad6018a0e32471eb9bfedb05ea44e。两套三件套的 COM9 DryRun、身份和资源预算均通过。

开发板经 COM9 写入并校验 GCC 三件套，只操作 CH342 的 COM9／COM10，未访问 J-Link。COM10 启动识别 CO5300 与 FT6146，RTC 经命令校时。先使 8 个计时器到期并占满活动槽，第 9 次创建得到容量拒绝；8 条提醒逐条 ACK 后活动计时器数从 8 回到 0，再创建成功。串口输入过快时有一次拼接成无效命令，随后降低发送速率并依据终态结果确认实际成功创建的 8 项，不把发送行数当成功数。

计时器 id=10, occurrence=10 稍后 9 分钟，记录从 SNOOZED 回到 PRESENTING，路由自动再次打开提醒页；操作者点“停止”后，提醒和活动计时器均归零。闹钟 id=1, occurrence=1 稍后后由操作者在页面禁用保存，读回 enabled=0、提醒状态 HELD。原稍后命令至到期后读数间隔 559.821 秒，未重新弹出；随后串口 ACK 这条保留记录并删除测试闹钟，最终闹钟、提醒和计时器均为 0。GUI Home 注入返回根页，触摸溢出 5 次采样均为 0，采集窗口内未见 HardFault、断言或显示绘制超时。

这次板测证明正常使用路径和真实九分钟单调时钟到期；没有在板上注入内存耗尽或精确竞态。起始与结束时页面栈和缓存状态不同，主堆数值不能作为“无泄漏”的同状态对照。启动仍出现既有 flash1 FAL 报错，持久化属于 D15；#8、#10 继续单独跟踪。Issue #14 在架构师复核前保持打开。
