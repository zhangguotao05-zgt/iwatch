模块接口与开发任务 v1

2026-09-15 · 接口与任务为待实现契约 · 固件实现基线：761d355

本文规定模块所有权、接口输入输出、资源限制和开发依赖。它是后续代码评审和测试的共同依据，不表示这些接口已经存在。功能行为见 页面契约，现有问题见 架构复审。

2. 命令、结果与幂等契约

短命令按值复制，固定 32 B。下例是后续头文件布局要求；目标编译器必须使用 _Static_assert(sizeof(iw_command_t) == 32) 验证，不能把裸结构内存直接当作磁盘格式。

typedef struct {
    uint32_t session_id;
    uint32_t request_id;
    uint32_t page_generation;
    uint16_t page_id;
    uint16_t opcode;
    uint16_t version;
    uint16_t payload_bytes;
    uint8_t  payload[12];
} iw_command_t;

request_id 由唯一 GUI 命令入口单调分配，同一服务会话内不复用；达到上限返回错误，不悄然回绕。session_id 区分服务重建会话，不能依赖随机撞号概率作为正确性保证。当前命令仅在本机 RAM 中流转，不接受跨冷启动的命令重放。

消息先检查 version、opcode 与精确 payload_bytes，再校验范围。12 B 载荷由具名编码函数写入，不用未对齐的强制类型转换。首期接口族如下；数值 opcode 在头文件中固定，不能依赖枚举插入顺序改变协议。

命令族载荷字段 / 字节数受理规则
SET_BRIGHTNESSlevel:u8、kind:u8、reserved:u16、expected_revision:u32、setting_sequence:u32；12 B。kind 为 PREVIEW/FINAL；每字段独立递增 sequence。FINAL 使用同一编辑会话最新 revision，旧页面的过期修改返回冲突。
SET_CLOCKutc_seconds:i64、offset_minutes:i16、reserved:u16；12 B。检查 2000–2099 范围及偏移；独占时间编辑会话；提交成功后增加 clock_revision。
TIMER_CREATEduration_ms:u32；4 B。1,000–86,400,000 ms；分配 ID、模型槽和提醒槽后才受理。
TIMER_PAUSE / RESUME / CANCEL / RESTARTtimer_id:u32、expected_revision:u32；8 B。先推进到期，再比较实体版本和状态；旧 revision 返回 STATE_CONFLICT。

接口（计划）调用者 / 返回值所有权与超时
iw_command_submit(command)GUI → service；QUEUED 或 BUSY_NO_ADMISSION / INVALID。QUEUED 只表示已入队；没有代表实际硬件执行成功。调用立即返回，不等待服务。
iw_result_get(session, request, out)GUI 读取已受理/进行中/成功/失败/结果已过期。复制结果；回执队列满时仍能查询；过期结果不得触发重新执行。
iw_result_ack(token)GUI 通知该结果已处理。释放可回收账本槽，但已受理序号水位保留，旧请求不能再次执行。
iw_snapshot_read(topic, out, capacity)GUI / 诊断读取版本化副本。锁内只做有界复制，锁外排版/日志；长度不足返回 required size，不写半份快照。
iw_display_request(value, seq)service 写最新显示目标，GUI 安全边界消费。旧 seq 的完成结果可记录，但不能覆盖更新目标；超时查询实际应用序号。
iw_clock_read(out)服务获得 mono_ms、utc_ms、valid、clock_revision。64 位值用受保护快照；32 位 MCU 不直接裸读两个半字。

命令队列 16 条；未终结命令最多 16 条；结果账本 32 槽（活动与已完成合计，每槽预算不超过 96 B）。服务受理前先保留模型容量、账本槽和需要的提醒槽。任何一项失败都不产生业务副作用。完成结果优先保留到 GUI 确认，压力下只回收已确认终态；没有可回收槽时拒绝新受理。

重复 token：账本仍在则返回同一执行结果；token 早于已受理序号水位而记录已回收则返回 RESULT_EXPIRED，绝不重做操作。GUI 只按顺序生成新请求，重试仍用原 token。一个未受理请求被后来的新请求越过后，需要显式建立新操作才能获得新 token。服务重启只保证持久化模型恢复，不承诺任意命令跨重启恰好执行一次。

全局 GUI 消息泵即使页面已退出仍须处理结果并 ACK；页面 generation 仅决定是否把结果交给 Presenter。页面消失不能导致账本永远占满。资源句柄的完成消息被忽略时，持有者仍必须释放引用。

连续亮度只保留一个尚未送出的最新目标。已经受理、但尚未执行且被更大 sequence 替代的预览必须结束为 SUPERSEDED，并由 GUI 确认回收账本；不能让旧请求永久 IN_PROGRESS。已经执行的旧值保留实际 applied 记录，新的目标继续收敛。已受理的 FINAL 不由旧预览替代；其后明确的新操作可覆盖它，但仍需给出各自终态。

统一状态 / 错误页面处理
QUEUED / ACCEPTED / IN_PROGRESS显示忙态，可退出；按操作 deadline 查询结果，禁止永久转圈。
OK_APPLIED / OK_PERSISTED更新实际值；只有后者可声明跨重启保存。
SUPERSEDED旧预览已被更新目标替代；结束旧等待并查询最新模型，不显示设备故障，也不谎称该旧值曾应用。
INVALID / STATE_CONFLICT保持已知状态，刷新模型，指出输入或状态冲突。
BUSY_NO_ADMISSION / CAPACITY保留草稿，可重试；不能显示操作已成功。
ABSENT / DEVICE_FAULT / NO_MEMORY / STORAGE_UNAVAILABLE显示能力或可恢复错误；保留返回入口。
UNCONFIRMED_TIMEOUT / RESULT_EXPIRED查询模型和操作版本；超时不等同于撤销，不能用新 token 自动重做非幂等操作。

首期交互超时目标：普通命令受理 100 ms、亮度执行确认 250 ms、设置存储 2 s。它们是诊断与 UI 状态阈值；驱动执行预算须量测后调整。超时不杀死正在执行的线程，也不假定硬件已经撤销。

ResourceHandleslot、generation、type；实际指针只在管理器中。最多 64 个句柄；槽复用时 generation 变更，防止旧句柄指向新图。
PageResumepage_id、选中实体 ID、滚动位置、有限编辑草稿。最多 6 份历史摘要，每份 ≤128 B；不含 lv_obj 指针。

分配前验证乘法溢出、长宽范围和最大解码大小；文本长度以 UTF-8 字节计算并保留完整码点。时间差使用同一来源的时间戳。测量单位定义在模型中：心率 bpm，SpO₂ 百分数的定点比例需由适配明确，电压 mV、步数 count；原始 ADC 值不能冒充物理单位。

实体 ID、revision、occurrence、句柄 generation 和设置 sequence 的边界各自显式检查；耗尽后拒绝新增或重建受控会话，不能在仍有旧引用时静默回绕。missed_count 与诊断丢弃计数使用饱和累加。句柄编码由各自管理器声明并静态校验位宽，调用者只能校验/复制不拆解。

32 位 tick 在 1000 Hz 时约 49.7 天回绕。扩展由一个 owner 至少每秒取样，使用无符号差；必须保证两次取样相隔小于一整轮 tick。深睡期间 tick 连续性没有保证，M4 使用已验证 RTC/AON 补偿，不把简单的高位加一当作长期休眠解决方案。

4. 调度与显示所有权

RT-Thread 中数值越小优先级越高：沿用 tpread=10、lcd_task=12、app_watch=19。新增 iw_service=17/4 KiB；iw_io=22/4 KiB 在存储阶段引入；iw_super=15/2 KiB 在监督阶段引入。GUI 原 16 KiB 栈保留。新增固定数据预算计入主堆/静态 RAM，不能与原预算重复累计。

  1. GUI 醒来先限量消费离散事件，再处理服务结果/脏主题；每轮最多 8 项或 2 ms，超出留到下轮。
  2. 有安全显示请求时，在无未完成传输的边界应用亮度；不等待 DMA、不持业务模型锁。若 SDK 控制接口会阻塞，先测量并通过现有 LCD 串行任务适配，不能直接塞进 GUI 循环。
  3. 调用 LVGL 定时与渲染处理，保存进度和耗时；最后等待输入/服务唤醒或最近 LVGL 截止时间。
  4. ACTIVE 时等待上限 20 ms；LVGL “无 timer”哨兵、0 delay、超范围值显式转换。没有工作时允许睡眠等待，禁止持续忙轮询。
  5. service 每轮先推进到期任务，再处理有限命令、执行完成和状态变化；更新一次快照后阻塞到下一期限或消息。一次连续 CPU 工作目标 ≤1 ms。

锁规则：IRQ 临界区仅保护小型输入队列索引/事件复制；线程模型用优先级继承互斥锁或经验证的消息所有权。禁止拿模型锁调用设备、文件、LVGL 或发送可能等待的消息。64 位快照读写、取消和统计读也遵守同一同步规则。

服务的显示请求使用单槽最新目标与 applied_seq，忙态可合并；GUI 报告当前实际 applied_seq，服务忽略低于已应用序号的迟到结果。设置预览不与“关闭显示”“睡眠”并发修改设备：电源关闭请求优先，亮度在下次安全唤醒时应用。

GUI 唤醒事件允许合并，业务结果不可仅靠一个唤醒位保存。关中断只能处理当前 HCPU 共享数据，未来跨 HCPU/LCPU 通信必须增加 mailbox/IPC，不能沿用本地 IRQ 临界区。

5. 页面生命周期与路由事务

项目只存当前导航意图、候选目标和 resume 摘要；真实运行栈归 SiFli。一个导航从 IDLE→PREPARING→TRANSITIONING→COMMITTED，准备失败走 ABORTED 回当前页。只有收到目标 ONRESUME 且转场完成条件满足后，才提交历史和释放旧页转场资源；两个事件次序均须测试。

事件动作顺序失败规则
创建验证 route/能力/深度→分配 scope→创建根对象→登记子资源→订阅快照。任一步失败按逆序退还；不得先写“当前页面已切换”。
恢复可见读最新模型→更新一次布局→恢复可见动画/刷新→登记焦点。资源缺失只替换该内容；页面模型不从过时控件回填。
暂停停止可见动画/定时刷新→保存滚动摘要→释放可回收快照。后台业务不取消；触摸状态 CANCEL，下一页需新按压。
停止generation 失效→取消/注销外部回调→取消任务订阅→停止动画/timer→释放句柄→删除项目拥有对象→释放状态。SDK 拥有的屏幕根节点交由框架删除；实现前用生命周期追踪验证实际顺序，避免双重删除。

scope 上限：每页最多 8 个 timer、8 个动画登记、16 个订阅/外部回调、16 个资源句柄。超额返回容量错误并保留现有页面。scope 登记空间包含在每页状态预算内。display 级回调必须显式注销，删除页面树不会自动清除这些回调。

最多 2 个运行 App、单 App 子页深度 8、历史 6。转场只允许一笔事务；在途普通请求返回 BUSY；返回意图占一个专用待处理槽，可覆盖重复返回。关键提醒先记账，等待合法层级接管；普通通知不能打断关键确认。

首期通过 SDK 公开 gui_app_create_page_ext、公开手动转场入口和生命周期实现，不调用 gui_app_int.h 的私有中断函数。动画终止能力未验证时使用完成后返回；后续可在同一 navigator 接口内升级可中断转场。

6. 资源、美术与视觉开发约束

资源清单每项记录 ID、类型、许可证来源、包版本、尺寸、像素格式、压缩长度、最大解码长度、校验值和 fallback。内置启动字体/数字表盘/错误图标不依赖 NAND 文件系统；大照片和复杂动态资源后移到 M4/M5。

资源类别初始配额回收与降级
绘制缓冲双 50 行 RGB565 = 78,000 B，SDK 所有。传输完成前禁止覆盖；不计入页面独占缓存两次。
页面快照共 768 KiB；两张全屏 RGB565 共 702,000 B。预算只剩约 84 KiB，不能再附加任意全屏透明层；预留失败时关闭该转场效果。
图像缓存现有 PSRAM 2,100,000 B + SRAM 50,000 B；字体池现有 160,000 B。按资源句柄 pin/use 完成解锁；LRU 只回收既未被引用、也未参与传输的条目。
UI PSRAM 工作集首期 ≤8 MiB，包含上述缓存、快照、字形、临时层和屏幕缓冲实际所在池。维护去重账本；渲染中临时层失败回 Q0，不改变布局与业务状态。
主 RAM业务固定池新增暂留 32 KiB，轻量恢复层另留 16 KiB；全流程主堆峰值 ≤1.2 MiB。与已有实际主堆容量比对，保留 ≥25% 空闲；检查最大空闲块而非仅总空闲。

RGBA 全屏临时层为 390×450×4=702,000 B，已近一份快照总预算。Q1 采用预烘焙高光/边缘与局部透明，默认不做全屏实时模糊。Q2 开启前记录新增中间层尺寸与存活时间；RGB565 色阶通过实屏图检查，HTML 预览颜色不能替代 AMOLED 验收。

每个代表页先交付 390×450 的布局稿、全部状态清单、中文/大字号和圆角裁切样例，再落成组件。第一批视觉验收样例为数字表盘、列表、亮度选择器、计时详情和提醒层；组件通过后再扩展蜂窝图标与复杂表盘。

7. 持久化、崩溃恢复与监督

M1–M3 业务模型在 RAM 中运行；M4 才开放经过验证的持久化 Provider。文件系统未挂载、只读或未知 schema 均保留原数据并使用会话默认值，禁止失败后自动格式化。UI 展示已保存状态必须以存储回执为准。

设置记录的逻辑格式：magic、schema_version、record_kind、sequence、payload_length、payload_crc、payload；序列化明确字节序和长度，不保存指针/编译器填充。先向非当前 A/B 位置写完整记录→flush/close→回读校验→提交标记并同步→确认当前记录。启动选择最新完整记录；两份都无效则默认值并保留原文件用于诊断。

A/B 方案必须运行在确认了 ECC、坏块映射和文件系统提交语义的层上。CRC 能发现损坏，不能保证两个文件不会共用一个被破坏的物理擦除块；提交标记也不能自行创造原子写。只有实际掉电矩阵通过后才能宣称已具备所测条件下的恢复能力。

计时检查点存逻辑状态、剩余时间、RTC 对照及其可信性，不保存下次启动不能继续使用的绝对 mono deadline。复位后 RTC 连续性不明则恢复待确认；已过期项合并为可查看的错过记录，不在启动时狂响全部历史闹钟。

监督先采集 GUI loop、服务 batch、显示提交/完成、I/O 活动的进度值。每个模块登记工作 deadline 和允许休眠状态，空闲不推进业务并不算死锁。看门狗只在全部必须存活的模块仍有进展或处于批准等待时喂养；超时只能请求受控恢复，不能从监督线程跨线程调用 LVGL。

本地恢复入口保留：组件资源错误→占位；页面构造失败→已存在的恢复层；设备故障→能力 fault；GUI 或显示无法收敛→有限尝试后受控重启。连续启动失败使用有可靠保存基础的启动计数才可进入安全模式，不能提前承诺现有硬件具备这一机制。
