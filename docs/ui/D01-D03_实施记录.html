D01–D03 实施与验证记录

日期：2026-09-15。范围：既有演示页面生命周期、构建来源及 GUI 输入基础。硬件基线为 SF32LB58-DevKit-LCD A128R32N1 / A1，390×450 CO5300 QSPI AMOLED + FT6146。沿用 HCPU 240 MHz、LCPU 48 MHz 配置、16 KiB GUI 栈与 50 行双绘制缓冲；这些是现有基线，本轮没有新的板上测量。

1. 页面生命周期与失败回滚

表盘管理器先从链表摘除描述符，再调用暂停/反初始化并释放。管理器增加就绪与停止标志，空列表、重复退出、部分注册和对象创建失败均走受控路径；插件失败不会被标记为活动状态。暂停、定时器回收及反初始化可重复调用，图片缓存先解除控件引用再释放。退出后清除上下文指针，只删除本页创建的对象，框架持有的根屏幕仍由框架删除。

桌面把自身作为 display 回调的用户数据，退出先按“回调函数 + 用户数据”注销，再停止动画、删除图标及页面、释放数组和管理器。图标删除回调只释放自己的命令字符串。状态栏先删除控件树，再释放字体缓存；各阶段允许部分构造回滚。

gui_core/iw_recovery.c 在启动演示页面前创建常驻错误层，使用已有 Montserrat 20 点内置字库。错误路径只显示现有对象，不临时申请整屏图片或大字库。当前提示使用短英文，D07 负责中文最小字库与产品视觉。错误层本身若建立失败，停止 GUI 启动并记录日志；不谎称此时仍能显示错误页。

测试直接抽取当前生产文件的完整被测函数并编入 C 测试，使用 AddressSanitizer 与所有权替身：三个描述符退出循环 1,000 次、桌面循环 1,000 次、字体销毁循环 100 次；桌面管理器/数组/页面对象四个分配点及绘制失败回滚；三个表盘插件分别 10、10、6 个分配点逐一失败。测试不复制退出实现。替身覆盖项目拥有的状态、控件返回值、缓存和定时器；不模拟 LVGL 内部所有 style/event 分配，不能据此承诺整个 SDK 在任意堆耗尽下都可恢复。

2. 固定构建来源与存储配置

机器配置以 build_profiles.json 为准。SDK 固定为 421126d9f476ed8e2a6f0b0ca28a9f241c182e65，要求工作区及子模块干净；Bluetooth 子模块为 4d081f8fc4bfc0199bdccc1bb36b9fdc40e7240c，SiliconSchema 为 304658c6edd5497211b7d152932327ce6e4450ff。本机隔离检出目录为 C:\OpenSiFli\SiFli-SDK-v2.5.1-iwatch-locked。

Profile存储目标状态
DEV_A128_NAND128 MiB 外部 NAND，PSRAM1/2 各 16 MiB；main 装载槽及运行窗均 6 MiB。本轮唯一可构建目标；分区文件未新增修改。
PRODUCT_N16_NOR1 MiB SiP NOR + 16 MiB 外部 NOR 的设计目标。禁止构建；BSP、引导、PSRAM 和最终分区未验证，不能套用开发板镜像。

两个目标的共同资源设计上限先定义为：启动/错误页内置字库 ≤128 KiB，首个可运行批的必要外置字体与图片合计 ≤4 MiB；扩展资源单独分包。它们是 D07/D15 的设计门槛，尚未完成字体裁剪或资源迁移，不代表 PRODUCT 已预留可用分区。原开发板 32 MiB 资源包设想不能作为共同下限。

实际公共 BSP 来自锁定 SDK 的 customer/boards/sf32lb58-lcd_base，四个源文件为 bsp_init.c、bsp_pinmux.c、bsp_lcd_tp.c、bsp_power.c。仓库同名基础板目录仍为参考副本。构建脚本明确映射整个 SDK 基础目录，主镜像、引导镜像各自生成对象文件；来源清单记录实际 SDK 路径与逐文件哈希。

GCC 固定 14.2.1 20241119；Keil 固定 Arm Compiler 6.16。构建前后核对项目输入哈希、SDK 身份和配置，构建后检查真实镜像大小及下载地址，并读取项目对象文件的 ELF .comment 核实实际编译器。Keil 的 --target=mdk5 在本版 SDK 设置 no_exec，只生成工程；脚本现在另行执行真实编译。工程包含 928 个有效源码引用。过去把生成日志当成真实 Keil 构建的表述已更正。

两个工具链共享 SCons 工作目录，由操作系统文件句柄锁互斥；并发启动会明确失败，异常退出后可重新获取。成功产物分别保存在 project/artifacts/DEV_A128_NAND/gcc 和 keil；包括三个 bin、对应 ELF/AXF、map、有效配置、下载清单、项目对象和 build_identity.json。这些本机构建文件不纳入 Git。手动 uVision 构建后原身份不再自动有效，须重新执行受检查入口。

镜像达到 6 MiB 槽的 85% 时预警；剩余不足 128 KiB、超槽、错地址、缺镜像、错工具链或配置变动均拒绝发布。现有完整中文字体约 3,939,852 B，尚未裁剪，D07 前必须验证内置最小字体和外置资源方案。此次不扩大镜像槽规避容量问题。

3. GUI 等待与输入取消

新增 core/iw_gui_wait 和 platform/iw_gui_port。KEY1 回调只写有界队列并发送唤醒事件；事件对象在 GUI 线程和输入注册之前建立。GUI 每轮先消费取消与输入，再运行 LVGL，再通过 OR+CLEAR 接收等待。禁止在等待前清空事件；因此消息在进入等待前到达仍会被锁存。无定时器哨兵和较长超时都限制到 20 ms，零超时至少让出一个 RTOS 节拍；当前 RT_TICK_PER_SECOND 固定为 1,000。触摸仍由 SDK 的缓冲和 LVGL 读定时器服务，取消时统一重置；本轮没有改写触摸驱动。

每轮输入最多消费八条或两毫秒，剩余队列继续触发唤醒。原始或语义缓冲溢出时取消整个未完成按压，清空待派发 Home，GUI 线程重置 LVGL 输入并让触摸等待释放。若队列溢出丢掉 RELEASE，则只有排空队列、物理电平持续释放 20 ms 后才重新武装，期间不合成旧单击。无符号节拍差值支持回绕。每键门控相互独立的核心用例已测；本轮实物注册仍只有 KEY1，KEY2/双击/旋转表冠属于 D09。

PM/DFU 仍关闭，构建身份检查会拒绝未经验证地启用这两个配置。这里的唤醒是活动 GUI 线程的事件唤醒，不代表芯片深睡、屏幕关断或升级路径已经完成。
