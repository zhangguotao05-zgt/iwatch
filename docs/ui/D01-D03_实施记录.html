1. 页面生命周期与失败回滚

表盘管理器先从链表摘除描述符，再执行暂停、反初始化和释放。就绪与停止标志使空列表、重复退出、部分注册和对象创建失败都能回到稳定状态；插件构造失败不会被记录为活动表盘。图片缓存先解除控件引用再释放，退出后清除上下文指针，只删除本页拥有的对象。

桌面退出时按“回调函数 + 用户数据”注销 display 回调，再停止动画、删除图标与页面并释放数组和管理器。状态栏先删除控件树，再释放字体缓存。gui_core/iw_recovery.c 在页面启动前建立常驻最小错误层，错误路径不临时申请整屏图片或大字库；D07 再补产品化中文错误页。

主机测试从生产文件抽取完整被测函数并用 AddressSanitizer 执行：三个描述符退出 1,000 轮、桌面构造与销毁 1,000 轮、字体销毁 100 轮；管理器、数组、页面、绘制和三个表盘插件的逐点失败路径全部通过。它覆盖本项目持有的对象、缓存和定时器，不把 LVGL 内部任意内存耗尽等同于已经验证。

3. GUI 等待、输入取消与触摸栈

core/iw_gui_wait 和 platform/iw_gui_port 统一 GUI 唤醒。KEY1 回调只写有界队列并发送事件；GUI 每轮先消费取消与输入，再运行 LVGL，最后通过 OR+CLEAR 接收等待。等待前不清事件，因此提前到达的输入仍被锁存。无定时器哨兵和长超时限制为 20 ms，零超时至少让出一个 RTOS 节拍；本配置为 1,000 tick/s。

每轮最多消费八条或两毫秒。队列溢出会取消未完成按压、清空待派发 Home，并在物理释放稳定 20 ms 后重新武装；不会因丢失 RELEASE 合成旧单击。触摸取消同时重置 LVGL 输入。KEY2、双击和旋转表冠仍属于 D09。

首轮压力测试发现 SDK tpread 的 1 KiB 栈峰值达到 78%，超过 75% 门槛，因此没有按首轮结果验收。项目随后引入 本地触摸线程实现，以 IW_TOUCH_THREAD_STACK_SIZE=2048 固定栈大小并在编译期限制最小值。SCons 和 Keil 都移除且只移除一个 SDK 原实现，再编译本地文件，避免重复符号或工具链分叉。最终压力峰值降到 27%。

iw_input_stat 记录接收、消费、拒绝、丢弃、取消、队列高水位和入队至 GUI 消费延迟；iw_input_stat_reset 清空统计计数与延迟直方图，便于划定一次板测窗口。执行清零前应先停止操作并确认 pending=0，该命令不会丢弃仍在队列中的输入。
