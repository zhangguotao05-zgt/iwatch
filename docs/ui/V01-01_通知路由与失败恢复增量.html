模式执行路径和断言边界
23侧键进入既有控制中心，按真实 scene/hit 选择普通锁／水锁；锁定期间普通通知到达，侧键、表冠单击／双击被真实 input_signal→iw_keys_intent 拦截。解锁后通知列表→详情→返回，确认取消／返回不删除。真实计时器到期与实际闹钟创建／到期分别覆盖确认页；后台通知到达，隐藏列表回调无作用，提醒关闭后恢复原列表，旧确认版本被拒绝。重新确认清除后，alerts、chronograph、alarms、服务统计及 key-port 锁上下文逐项不变。入口调用既有 iw_router_open，未模拟物理下拉。通知覆盖层不能再叠加控制中心，因此未伪造“确认页直接进入锁页”的 UI 路径。提醒 ACK 仅在隔离断言完成后作为明确收尾动作执行。
24经真实列表节点／命中进入详情；在真实页面 ONSTART 的 View frame 分配点失败，生命周期标 failed 并回滚原列表；账本版本不变、未提前标已读、未清除。取消注入后重试详情成功，才标已读，再实际返回／退出。仅验证一个确定的创建分配点，不是所有内存申请的全矩阵。
25旧列表帧遇新通知，点击触发状态变化提示；在真实 View update 取得新警告字体资源时失败。旧 notification_view_revision 保持，dirty 保留，账本 count/revision 不变；故障期间清除动作无副作用。调用生产 GUI 故障处理与路由恢复，重新进入列表后通知仍在，新 View 正确发布当前版本。只验证一个更新资源失败点；没有宣称失败时旧 scene 像素完整保留。按既有故障隔离／重建恢复，不做原地失败帧绘制。

  • 最终 run-05：configure、必要主机增量 build、mode 23、24、25 全部 exit 0。使用 MSVC /W4 /WX（保留项目既有 /wd4244）及 AddressSanitizer，断言启用。三个进程在 lv_deinit 后均为 live_bytes=0、live_blocks=0；不是全产品无泄漏或峰值预算证明。
  • run-01 的夹具错误：误把 key port 持久状态等同于 input_signal 临时计算的 OVERLAY；改为清除前后上下文一致断言。初次 Python 默认 GBK 解码构建日志失败，首次 build stdout 不完整；以后用 -X utf8，未伪造缺失日志。
  • run-02 的夹具错误：漏掉生产主循环的延迟字体回收安全点，收尾残留 10472 B／140 块；补调用同一 iw_font_collect 后 run-03 通过。保留失败，不当作生产泄漏修复。run-04 恢复严格 assert/oom_count 零值检查后通过；run-05 将新测试的固定字符串复制简化为结构初始化后通过。
  • 静态 static-03 门禁非零：三翻译单元、真实 compile_commands，clang-analyzer-* 保持启用，header-filter 使新增 inc 纳入报告；47 条可见诊断（45 安全 API 建议、1 va_list、1 SDK 枚举）。新增用例无剩余可见诊断。旧操作行源码对照在 audit.json，不是旧版分析器反跑，也不是 D 的关闭结论。

静态判读：日志包装的 vprintf 前已有 va_start/va_end；SDK LV_OBJ_FLAG_SCROLLABLE | LV_OBJ_FLAG_CLICKABLE 的位或被报告 EnumCastOutOfRange，当前抽取 inc 与原阶段 SHA-256 完全相同。二者没有被改动，本轮不为关闭分析器而改 SDK 或日志框架；C 仅记录需 D 判读。其余 API 建议来自未修改的固定长度／已有边界代码，不作为新增已确认漏洞，也不声称全部安全审计完成。static-01 漏显示头内诊断，static-02 补头后记录新增固定 memcpy 建议，该处已改为字符串初始化；原报告均保留。
