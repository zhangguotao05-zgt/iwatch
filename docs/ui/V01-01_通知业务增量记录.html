业务语义与责任边界

  • 复用 0501 通知列表、0502 通知详情与既有 RAM 普通通知账本；确认是列表模型子态，没有新服务／路由／生产假通知。
  • 进入确认记录整个普通账本 revision，不删除。期间新增、删除、首次标已读或淘汰使确认陈旧；确认失败逐字节不改账本，退出确认并显示通知变化。再次显式进入才能绑定新版本。重复进入不会偷偷换令牌。
  • 取消或 Back 只关闭确认；没有确认的直接确认无效。成功清除记录、count，并增加 revision；ID、sequence、evicted 保持单调。空账本成功不变，版本饱和且非空时失败不变。
  • 通知变化会刷新存活详情，删除／淘汰后 selected_notification_valid 为 false；打开已失效 ID 可显示既有失效提示，不转向另一条记录。只有详情 View 成功创建才尝试标已读。
  • 记录实际已构造 View 的账本版本。新通知到达而旧帧尚未更新时，拒绝按旧行号打开新的对象或进入清除；安全点重绘后可重试。
  • 操作仍归 app_watch GUI 所有者。清除无动态分配、无服务命令、无 ACK/STOP，不修改锁、计时器、闹钟或关键提醒；固定清零 32 槽记录。两个页面版本字段增加 8 字节（结构对齐及目标占用以 GCC 结果为准）。

  • iw_notifications.c:113（新增）：非空 store、count 与 revision 验证后，目的为完整 records 数组，长度正好 sizeof(store->records)；不是外部长度。
