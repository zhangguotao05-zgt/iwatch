2026-09-17 · 固件源码 5d66e582e10456dd2b5d5576763a3ec019219555 · D07-D 原始阶段记录 · Issue #7

状态

D07-D 的组件、字体及回收部分已获架构认可。本轮触摸溢出整改已通过主机回归、双工具链检查和新 GCC 固件实机复验，已获架构复核批准（9088f52）。20% 与补测 80% 的完整采集窗口累计覆盖 9 次真实溢出，操作结束后均解除输入隔离。D07 整体审批通过；性能遗留已关联 Issue #8，Issue #7 以完成状态关闭，允许进入 D08。

根因和复现

旧驱动队列共 16 个槽、可用 15 个。满队列仍写入尾部，但不推进可读边界；满队列后输入 UP、DOWN，消费端可能只看到 DOWN。旧告警使用 8 位计数，仅值为 1 时打印，不能据此推算溢出次数。

从修改前生产文件原样提取队列写入和读取函数，仅替换 RTOS 边界：填满 15 个 DOWN，再写 UP、DOWN，连续读取 17 次。结果为 full_writes=2 warnings=1 read_up=0 read_down=17 edge_lost=1。历史复现源码与输出独立保存，不用新驱动覆盖。

取消、隔离与重新接受输入

  1. 生产线程发现队列满，累加溢出与丢弃计数，清空旧队列，锁存取消请求并进入隔离态。之后继续记录真实触摸状态，不向 GUI 排入新的按压。
  2. 设备通知只唤醒 GUI。GUI 主循环及物理指针读取回调共用取消入口，在 GUI 线程调用 lv_indev_reset、lv_indev_wait_release，随后确认驱动取消。持驱动互斥锁期间不调用 LVGL 或唤醒回调。
  3. 隔离期间读取返回静默 UP，但只有 GUI 确认取消后、驱动实际采样为 UP 且被读取，才解除隔离。UP 后立即再按且未被 GUI 消费时仍保持隔离，宁可舍弃这一手势，也不把它接到上一手势。
  4. 页面或字体故障触发全局输入取消时，同样清理驱动旧样本。旧页面剩余按压不能穿透到新页面。正常新手势需经过真实释放后重新按下。
  5. 固定 SDK 的取消事件是 LV_EVENT_INDEV_RESET。公共组件补齐此事件的按压动效复位，恢复自身缩放和 LVGL 按下状态，不发出点击动作。

项目物理指针适配层接管 SDK 的读取和接收通知回调，设备创建及生命期仍由原适配层管理。连续读取依据真实队列深度，不再使用 SDK 的未读通知计数；清空队列后不会因历史通知积压重复读样本。初始化要求目标只有一个物理指针设备。没有扩队列、动态分配、关中断访问设备或新增 SDK 补丁。

源码入口：platform/iw_drv_touch.c、iw_touch.h、iw_touch_input.c/.h、gui_apps/watch_demo.c 和 gui_core/iw_components.c。

可查询计数

串口命令 iw_touch_stat 输出以下快照；所有累计计数为 32 位饱和计数，仅重启清零。快照在驱动互斥锁内复制，打印在锁外执行。

字段含义
overflow满队列进入隔离态的累计次数；进入隔离后已没有满队列，后续被抑制的采样计入 discarded。
discarded溢出时清掉的旧样本、触发该次溢出的样本、隔离期间采样，以及全局取消清掉的旧队列样本总数。
cancel / recoveryGUI 已执行驱动取消确认次数／消费真实释放后解除隔离次数，包含页面全局取消，不仅是溢出。同一隔离期可收到多次全局取消，两个累计值不要求相等；是否仍隔离由 pending/wait/down 判断。
queued / high当前深度／启动以来最高深度，上限 15。
pending / wait / down待 GUI 取消／隔离等待释放／最新物理样本为按下。
