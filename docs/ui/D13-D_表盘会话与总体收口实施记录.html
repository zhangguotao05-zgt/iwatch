D13-D 表盘会话与总体收口实施记录

2026-09-21 · Issue #15 · 设计基线 c7617c2 · 实现提交 2473b58 · 当前状态：主机、GCC、Keil 已通过；开发板复核待完成

本页把 D13 的剩余开发目标写成可执行的验收契约。它记录当前实现和证据边界，不提前宣称 D13 最终收口。代码注释、测试日志和工程文档按项目约定使用中文；外部 SDK 的原始注释不在本页改写。

产品目标

当前产品目标是一个 390×450、离线可运行的 Apple Watch 风格界面基线：表盘、蜂窝应用列表、控制中心、通知、智能叠放、最近 App、设置、计时器、闹钟和两种输入锁在同一套路由、输入仲裁和资源回收规则下工作。D13 只负责界面会话与覆盖层，不把联网、微信/支付宝、健康传感器算法或生产级 Apple 兼容性写入本阶段完成条件。

本阶段可交付目标

  1. 长按当前表盘约 700 ms 只触发一次表盘选择器，松手不会追加点击；选择器提供两个稳定 ID：DIGITAL=1、MODULAR_LOCAL=2。
  2. 编辑器以值复制方式维护草稿，支持强调色、中心信息、左侧快捷入口、右侧快捷入口四项配置；数字表盘不显示不可用的模块字段。
  3. 取消、返回、显示能力缺失、路由失败和 revision 冲突都保留原表盘配置；只有目标页成功创建并完成路由后才提交候选配置。
  4. 覆盖层、页面和字体继续使用既有 owner、固定节点和安全点回收规则，不为预览创建全屏缓存，不引入新的长期堆对象。
  5. 把目标、版本、镜像身份、测试分层和板测门槛写入仓库，架构师可以按同一基线独立复核。

表盘会话契约

阶段输入状态变化失败行为
进入表盘长按或编辑入口创建 face_draft，复制当前 session 和 expected_revision页面创建失败时保持当前表盘，显示已有应急层
字段编辑颜色、中心、左右快捷入口只修改草稿，不增加 session revision非法枚举值被拒绝，草稿保持上一个有效值
取消取消按钮、Back、Home 或覆盖层失效清空草稿和 pending 事务当前表盘配置、revision 和历史均不变
应用选择按钮检查显示能力和 expected_revision，建立 pending candidate冲突或能力缺失显示“时间设置已变化”/“显示不可用”，留在编辑器
提交目标页成功创建、路由成功提交候选配置，revision 单调增加，清空 pending任一阶段失败都回滚到 previous session

应用动作采用两阶段提交：控制器先保存 face_previous 和 face_pending，路由器只在业务页成功进入后调用 commit；路由拒绝、返回或能力竞态调用 rollback。这样不会出现“画面没有切换但表盘已经改变”的半提交状态。

实现与所有权

文件职责
src/gui_core/iw_product_scene.[ch]选择器、编辑器和表盘预览；固定节点、390×450 边界和可用字段布局。
src/gui_core/iw_product_view.[ch]长按识别、松手抑制和页面生命周期；不在输入回调中直接删除对象。
src/gui_core/iw_routes.c将 FACE_PICKER、FACE_EDITOR 注册为可用页面。
src/platform/iw_product_controller.[ch]session 默认值、枚举校验、草稿、revision 冲突和 pending 事务所有权。
src/platform/iw_router.c提交/回滚与路由结果绑定；请求失败时不遗留半提交状态。

本阶段不改变 D13-C 的锁优先级和输入契约：水锁仍先屏蔽触摸和 KEY2，普通输入锁仍要求 KEY1 长按并真实松手。表盘编辑只在解锁后的普通路由上下文中工作。

验证结果

层级结果证据与限制
主机 C 回归通过产品矩阵包含选择器、长按、编辑布局、取消、revision 冲突、显示能力撤销；组件 OOM、路由、生命周期和像素对照保持通过。
产品矩阵通过组件 OOM 37 点、绘制 OOM 47 点、行级失败 5/5/5 点、1000 轮控制器与路由循环通过。
GCC通过DEV_A128_NAND，main.bin 1,951,372 B，占 6 MiB 槽 31.016%；精确 SHA-256 以 artifacts/DEV_A128_NAND/gcc/build_identity.json 和同目录镜像为准。
Keil通过DEV_A128_NAND，main.bin 1,876,672 B，占 29.829%；精确 SHA-256 以 artifacts/DEV_A128_NAND/keil/build_identity.json 和同目录镜像为准。
完整 Python 门禁未宣称通过本机原版 SDK 目录仍含 D07 补丁，官方 clean-base 检查会主动阻止运行；没有绕过该门禁，也没有把 C 测试结果冒充完整 Python 门禁。

最终归档的两个 build_identity.json 都记录固定 SDK 421126d9 和构建时仓库 HEAD；构建身份字段以归档文件为准，不由本页手工覆盖。当前构建产物只证明源码、工具链、SDK 和资源预算闭环；它不替代开发板烧录、冷启动、触摸和实物按键验收。

开发板门槛

项目状态要求
三件套待刷写只允许同一 DEV_A128_NAND 归档的 Bootloader、GCC main、FTab，经 COM9 写入并回读校验。
表盘会话待实测长按进入、两种表盘、四项草稿、取消、应用、冲突/能力失败回滚、重复进出和内存采样。

证据采集待实测COM10 保存原始启动和交互日志，记录镜像哈希、时间、亮度、页面结果；全程不操作 J-Link。

明确不在本次收口的内容

  • Issue #8：长文输入延迟和触摸溢出频率；历史最大 215 ms 继续保留，不宣称达到 30 FPS。
  • Issue #10：半黑半白和 LCD/draw_core 异常；一次自动恢复不能证明根因已解决。
  • D15：flash1 FAL、NAND 坏块/ECC、亮度和表盘配置掉电保存；当前表盘配置是会话状态。
  • 联网、微信、支付宝、健康心率/血氧算法和生产级外壳/PCB；这些属于后续产品阶段。
