1. 结论与版本范围

优先建立清楚的信息层级、稳定的系统导航和完整的操作反馈，再逐页接近 Apple Watch 的视觉表现。大数字、胶囊按钮或玻璃高光单独出现，都不足以形成一致的手表体验。当前五类共享组件、字体服务和只读主题可以继续使用；下一步应通过具体页面检验这些基础能力。

本文是设计研究与后续适配建议。不改动已批准的 D07 预算、主题参数、接口和验收结论。撰写时 D07-C 正在架构复核，D07-D 尚未完成；新增建议在对应任务中评审后实施。

下文使用三种标记：官方依据能追溯到 Apple 的说明；项目现状能追溯到当前源码或验收文档；适配建议针对本项目提出、尚未全部实现的设计决策。

Series 11 是硬件型号，界面还取决于 watchOS 版本、语言、地区及辅助功能设置。研究沿用项目已确定的 watchOS 26，系统按键以版本固定的用户指南为准，视觉以 WWDC25 和 watchOS 26 UI Kit 为主要参考。官方入口现已包含 watchOS 27 信息；实时更新的 HIG 用于补充通用原则，不据此把目标版本悄悄升级。[S01] [S02] [S03] [S04]

Apple 官方指南主要面向运行在 watchOS 内的 App，我们还需要实现表盘、桌面和系统输入层。因此，App 内返回、系统 Home、关闭弹层必须分开建模。SwiftUI、WidgetKit 和系统材质 API 是参考平台的实现方式，本项目借鉴其行为与层级，落地仍使用现有 C 服务和 LVGL。

2. 用户提供的文章如何使用

已读取《WatchOS 系统篇》正文。页面标注 2023-11-19，包含 watchOS 8、旧组件模板等内容；适合作为中文入门提纲，不宜作为 watchOS 26 的尺寸、材质或行为依据。以下逐项对照只采用已核实的官方说明。[S05]

文章中的方向本次核对结果项目处理
交互短、重点清楚与现行平台设计原则一致。[S06]首页先给当前结果和主要动作，更多内容放详情。
偏向统一黑色底面watchOS 10 已明确支持全屏色彩和图片来表达信息。不能理解成所有页面必须黑底。[S07]系统列表保留黑底；天气、运动等业务背景以后按具体页面评估。
表盘组件的数量与模板官方说明的是不同表盘支持的槽位，并非每张表盘必须放一个或固定四个；新旧模板需区分。[S08]先确定表盘布局和能力，再决定放几个有效数据入口。
线宽以 px 描述现行 complication 指南给出的通用线宽建议使用 point。[S08]不把文中的像素数当作 390×450 的硬指标，按实际视觉尺寸检查。
短通知点击后看长通知官方还描述了持续观看时从短通知切换到长通知的流程；点击不是唯一触发方式。[S09]保留摘要/详情两级；抬腕触发需传感与功耗能力支持。
通知背景的固定透明度当前指南按材质、内容和对比度组织层次；单一透明度无法定义新版外观。[S10]继续走主题 Q0/Q1，不把旧数值写死到每个页面。

使用方法：中文文章帮助建立术语和问题清单；具体界面回到官方指南、对应版本 UI Kit 和参考设备画面核实。尚未见到的原厂页面状态标记“待核对”，不凭类似界面推断。

3. 最值得借鉴的设计原则

官方依据watchOS 强调抬腕即可读懂、少量操作完成任务、浅层导航，并通过通知和表盘组件把相关信息直接带到用户面前。[S06]

原则适配建议页面评审问题
一眼看见重点一屏确定一个主要读数或任务；标题、主值、说明分层，避免同等强调多个元素。抬腕后先看见的是剩余时间，还是装饰和无关说明？
操作路径短开始、暂停、确认等常用动作放在容易命中的位置；低频参数进入详情。完成一个常用任务是否多绕了一层菜单？
先识别，再展开列表展示标题和关键摘要；长正文独立纵向滚动，返回保留合理的位置。列表里能否判断该打开哪一项？
位置与行为稳定同一类返回和确认保持位置；加载、失败、恢复不突然移动按钮。连续点击时是否误触到了状态变化后出现的另一动作？
表达真实状态未采集、过期、未接入分别显示；命令提交、实际生效和保存完成分别反馈。用户看到的“成功”能否对应真实服务结果？

本项目的视觉工作优先级建议为：信息顺序 → 字体与对齐 → 输入与返回 → 状态反馈 → 动效 → 材质细节。这是一条开发取舍顺序，不代表 Apple 公布了相同的工程流程。

4. 系统导航与输入

官方依据watchOS 10 起加强表冠在纵向滚动和分页中的作用，同时要求触摸能够完成对应操作。表冠按压由系统保留，普通 App 不自行接管。[S11] watchOS 26 的具体按键行为见版本固定的用户指南。[S02]

输入 / 层级watchOS 26 参考行为iwatch 的接入边界
表冠单击进入表盘或应用桌面。由系统层统一处理 Home；页面内返回另设语义，不让各 App 改写。
表冠双击打开 App 切换器。归 D09 输入仲裁及 D13 系统界面；不能照搬其他系统版本。
表冠旋转滚动、缩放或调整当前值。只交给当前焦点拥有者；编辑数值时避免同时滚动背景列表。
侧键单击打开控制中心。系统入口，优先级与锁定、弹层一起定义。
侧键双击 / 长按支付入口 / 电源与紧急相关操作。界面和能力分离；当前不具备真实支付、呼叫能力。
触摸完成选取、滚动及屏幕手势。纵向列表优先；没有旋钮时也能完成所有当前任务。

项目现状已验证的开发板输入是触摸和 KEY1，KEY1 当前承担工程入口/退出操作；它不等于已经实现了完整表冠。旋转编码器、第二实体键、触感反馈仍须分别接入与验证。

适配建议D08/D09 让页面只接收“返回、确认、旋转增量”等语义。系统层先处理锁定与弹层，再分发页面操作。拖动开始后取消候选点击；页面退出取消按下态和在途手势；双击、长按不能顺带产生一次单击。具体阈值仍使用现有设计的待调参数，不称为 Apple 原厂时序。

转场期间先保留已批准的“完成当前事务＋合并一个返回请求”策略，避免为了更像原厂动效破坏生命周期。D14 再评估中途反向与更连续的转场。组件诊断页 KEY1 的清理路径不作为最终导航结构。

5. 屏幕与布局适配

官方依据Series 11 的 46 mm 型号为 416×496 px；46 mm 是机壳规格，不是屏幕对角线。[S12] Apple 建议充分利用手表屏幕，减少不必要的留白，文字按钮通常铺满可用行宽，避免一行塞入过多控件。[S13]

我们的面板为 390×450 px。横向比例为 390/416＝0.9375，纵向约为 450/496＝0.9073，两者不同。整屏分别拉伸会改变圆形与字形；等比缩放也不能解决中文行数和按钮命中的问题。采用重新排版、图标等比、字号按角色确定的方式。

项目参数当前源码值适配含义
安全区 / 内容宽左右 18、上下 24；常规内容宽 354 px当前工程初值。避让圆角需面板边缘标尺确认；不能声称为 Apple 安全区。
间距4 / 8 / 12 / 16 / 24 px先消除页面间随机间距，再按场景做光学校正。
列表行最小 60 px双行中文按实际 line_height 增高，不把最小行高当固定行高。
卡片圆角 24、内边距 16 px正文、按钮、整页轮廓使用不同尺度，不给所有对象同一个圆角。
胶囊按钮高 60、圆角 30 px主要动作优先全宽，标签尽量简短。
图标 / 命中区图标 48、命中区至少 56×56 px视觉图形与可触区域分开；邻近命中区不能冲突。

参数来源：iw_theme.c、D07-C 组件契约。Apple 按钮指南中 44×44 pt 是通用触控建议，不等于 44×44 面板像素。watchOS 图像通常采用 @2x，44 pt 在该坐标体系下为 88 px；这也不能直接变成另一块面板的尺寸规定。现有 56 px 只能称为项目起点，需结合有效显示尺寸、佩戴距离和误触情况验收。[S14] [S15]

6. 字体、文案与图标

官方依据Apple 为 watchOS 使用 SF Compact 字体家族，以适应较窄的列宽和小字号；官方资源页提供 watchOS 26 的 Figma / Sketch UI Kit。[S03] [S16] 本项目应比较字体的视觉比例、字宽和基线，而不是只对齐字号数字。

语义角色当前 px使用与检查
主标题30短标题优先；过长转为页面内说明，不靠不断缩字适应。
正文 / 列表标题26主信息保持清晰；中文宽度、标点和数字混排按真实字形度量。
次级 / 注释22 / 20用于来源、单位、说明。重要错误原因不能缩成难读的小灰字。
数字64 / 80 / 96按最长内容选档；数字变化时位置稳定，检查冒号、负号、小数点和单位。
旧页兼容16 / 18 / 20 / 22 / 24 / 26 / 28继续保留，迁移时逐页回归；不能因新角色字号不同而一次删除。

项目现状当前子集字体为 336 字符、56,804 B；字号角色与字库覆盖是两件事。新页面每增加一条静态文案，都要更新输入清单并通过正式字体校验。浏览器示意图能显示一个字，不代表固件字库已经包含它。D07 字体方案

适配建议中文优先使用简短动词与明确结果，例如“开始”“暂停”“重新测量”；加载时写正在做什么，失败时给出原因和可执行动作。日期、时区、单位、最长中文标题、数值上限分别准备排版样本。涉及真实数值或操作结果时不随意截断，必要时换行或进入详情。

当前源码还没有三套真实字重资源；视觉规范中的 Regular / Medium / Semibold 是目标，不代表已经实现。不要把常规字重反复偏移绘制当作已完成的字体设计。数字对齐也需验证所选字体的真实度量，不把浏览器的等宽显示当作实机结论。

图标采用一致的视觉重量、圆角和有效图形面积；同一个动作在列表、通知和桌面中保持可识别关系。工程图标与字体资源记录来源和许可，UI Kit 用于查阅结构与对照，固件继续采用项目已确认可分发的资源。本文未将 Apple 字体、图标包或整套界面图复制进仓库。

7. 颜色、对比度与材质

官方依据Liquid Glass 用于浮在内容上方的导航和控件层；正文所在的内容层使用标准材质。这样可保留层级与位置感，避免每块内容都像漂浮控件。[S10] watchOS 26 更新了工具栏和按钮样式，自定义界面仍需检查可读性。[S01]

系统背景内容表面凸起表面强调色次级文字
层级项目建议应避免
正文、长列表、数据卡片稳定深色底面；用间距、字重与主次色分层。逐行动态模糊、持续闪动高光、低透明度文字。
导航、浮动按钮、弹层共用 Q0/Q1 轮廓与前景规则；必要时保留背景上下文。透明背景变化后按钮消失、把表面高光误做成进度提示。
业务主色表达选中、类别或重要数据；健康状态同时有文字或图形。只凭红绿区分成功与失败；所有页面整屏使用同一品牌色。
降低效果切到 Q0 时保持位置、命中区、文案和返回流程。降档后更换整个布局，或把低效果模式做成残缺页面。

项目现状Q0 不透明；Q1 表面不透明度为 224/255，使用受控高光。当前不是 Apple 的实时折射材质。Q2 尚未实现，也不是推进主要页面的前提。新增材质要分别计入主堆、字形池和绘制临时缓冲预算。

现有主题色的可复核检查

采用 W3C 的 sRGB 相对亮度比值 (L高 + 0.05) / (L低 + 0.05) 计算下列不透明色对。建议普通有效文字先以 4.5:1 做设计筛查；这不是宣布本机通过某项无障碍认证，也不把 LVGL 像素字号直接套进网页“大字”豁免。[S17] [S18]

前景 / 背景计算结果含义
#FFFFFF / #17181C17.74:1适合作为稳定内容层的主文字组合。
#B9BBC6 / #17181C9.28:1不透明次级文字仍保有较高对比。
#FFFFFF / #0A84FF3.65:1如果将强调蓝用作实底，不能自动认为小号白字已满足建议目标。
#000000 / #0A84FF5.76:1可作为蓝色实底的候选前景；是否采用还需页面视觉评审。

以上只是静态色值计算，不证明当前某个组件在实屏上失败或通过。半透明面必须用合成后的最不利背景重新检查；RGB565 量化、抗锯齿边缘、玻璃反光和显示亮度还需实屏观察。20% / 80% 是现有调试亮度命令值，不是测得的 nits。

8. 状态、反馈与动效

官方依据自定义按钮应有按下反馈；watchOS 的内容内按钮采用胶囊形，主要动作优先占满可用宽度。[S14] 动效应说明操作和层级，进入与退出方向有逻辑，避免让用户反复等待装饰性动画；减弱动态效果后仍要传达结果。[S19] [S20]

时刻界面应该表达本项目责任
按下已收到触摸；松开或拖出有明确变化。组件按下态，不等待业务线程回复才有反馈。
提交正在处理；相同动作不能连续生成重复命令。Presenter 生成请求，按钮进入等待；当前省略号只是局部反馈。
成功真实结果已经生效，而非仅进入队列。读取服务结果与快照；区分 target、applied 和 persisted。
失败 / 超时保留可信的旧状态，给原因与重试或返回。结束等待；业务失败不擅自升级成全局崩溃。
页面退出及时抵达确定的返回目标。取消输入与订阅，等待在途绘制安全结束；服务结果仍由全局通路回收。

项目现状主题提供按压 75 ms、普通导航 250 ms、App 转场 290 ms 等参数，按压缩放 0.97。这些是项目配置，不能称为测得的 Apple 动画常数；只有调用该效果的页面才具备相应行为。缩放绘制不得缩小命中区。

适配建议秒表、计时器和圆环用模型的实际时间/数值重绘，动画只负责表现；页面隐藏后暂停无必要动画。错误发生在绘制期间时先记录，等 GPU/LCD 安全点再按所有权回收，最后显示独立应急层。正常业务错误与字体/绘制资源故障使用不同处理路径。

动效时长、输入排队延迟、命令处理时间和屏幕刷新帧率要分开记录。现存长文滑动和触摸覆盖问题继续跟踪，主要页面成型后集中优化；本研究不增加“现在必须达到 30 FPS”这一放行条件，也不把诊断命令响应快等同于动画流畅。

9. 通知、表盘组件与特殊状态

场景官方依据本项目适配建议
通知摘要与详情短通知让人识别来源，长通知承载正文和可操作项；摘要应注意隐私。[S09] [S21]摘要先显示应用与事件；正文页可纵向滚动，常用动作放独立按钮。旧演示通知不等于手机通知同步已经实现。
表盘复杂功能核心价值是及时的数据，不只是 App 快捷图标；没有内容时要有占位。[S08]每个槽位带值、单位、有效性、更新时间与详情入口；过期数据不能继续冒充当前读数。
健康读数借鉴信息层级和组件模式，具体数据契约由项目负责。未接传感器用“—”和原因；演示数据持续标注“演示”。采集中与测量失败分开，不能显示正常范围占位数值。
常亮 / 抬腕 / 灭屏属于设备与系统能力，不能由一张暗色界面代表。D16 验证前不宣称完整 Always On。先定义暗屏隐私、唤醒输入是否被消费及亮度恢复目标，再做功耗和唤醒实测。
更大文字 / 更少运动Apple 强调文本适配、颜色以外的识别线索以及减少运动效果。[S17] [S20]逐页评估字号放大、增高与滚动；全局可用的设置页尚需接入。降低效果不能取消成功/失败反馈。

当前离线范围内，微信、支付宝、联网天气等入口如果保留，只表达已实现的本地能力或说明未接入。Siri、支付、后台同步不是换个图标即可获得的功能。这一边界沿用功能逻辑与页面契约。

10. 项目接入与开发顺序

以下对应已有任务，不创建一条与 D01–D18 平行的开发路线。研究所得的新要求先写入各页契约，涉及接口或预算变化时纳入对应任务评审。

现有基础 / 任务如何使用本研究验收重点
D07-C / D07-DScreenFrame 管页面骨架；ListRow 管列表；PillButton 管动作；StatePanel 管空/错/不可用；StatusBanner 管短反馈。按已批准方案完成状态、字号、Q0/Q1、返回和故障清理。Banner 限频/超时属于后续 Presenter，不假定组件已自动实现。
D08 / D09把 App 内返回、系统 Home、弹层关闭及表冠焦点规则落入路由和输入仲裁。转场连按、触摸取消、重复返回、锁定优先级；真实硬件与注入分别记录。
D10 首个可运行批数字表盘 → 应用列表 → 设置/亮度 → 校时 → 关于，逐页建立参考卡和完整状态。首屏可读、中文边界、结果回执、往返路径；先完成闭环再扩大页面数量。
D11 / D12计时、秒表与提醒采用大读数和清楚的主要动作。后台运行与到期模型正确；视觉不能通过动画次数计算时间。
D13 / D14控制中心、通知、智能叠放、切换器和复杂桌面遵守固定系统版本。层次清楚、手势不冲突；主要页面完成后评估转场和滑动性能。
D15–D18资源持久化、低功耗、真实数据 Provider 和佩戴版适配逐项接入。存储故障、恢复边界、能力状态、实际触控尺寸及整机长期使用。

进入页面开发前应补齐的设计资料

  1. 参考卡：每页保存系统版本、机型、语言、来源链接和已观察到的状态；HIG 不能替代实际页面参考。
  2. 重排稿：在 390×450 坐标下给出边界、字号角色、主动作和滚动范围；不要整屏缩放截图。
  3. 状态稿：画出加载、空、正常、失败、不可用和返回；先确定数据来源与提交反馈。
  4. 资源表：新增文字、图标和位图分别登记；容量检查继续绑定正式字体清单和双工具链构建身份。
  5. 对照说明：记录真实旋钮、触感、字重、材质等差异，以及本轮是否接受。未核实的参数保持待定。

目前还需要在后续页面任务中确定：最终物理触控尺寸、角落工具栏占位、长标题规则、常用数字的字宽、各 App 背景色及能力不可用文案。现有主题不应在缺乏页面样本时一次性重写。

11. 页面交付与验收清单

建议每页以 HTML 参考卡交付，下表是可直接使用的字段。状态统一分为“未实现、主机通过、目标构建通过、实屏通过”，并写明版本，不以一项替代另一项。

字段必须记录
身份与来源page_id、参考系统小版本、语言/地区、参考来源、项目提交、主题与资源版本。
路径入口、父级、内部返回、Home、弹层、转场中返回、重新进入后的落点。
数据Provider / snapshot、单位、有效期、未接入和演示标记、命令与结果对应关系。
布局安全区、主要信息、字号角色、命中区、内容高度、最长中文和数字边界。
交互状态按下、拖动取消、等待防重、成功、失败、超时、禁用、退出。
视觉可读性低/高亮度、复杂背景、灰阶、Q0/Q1、减弱动态效果、字号与字重差异。
资源与故障字体引用、主堆与字形池、绘制临时内存、失败点、重复退出和恢复。
性能固定场景、采集开销、输入延迟、首帧时间、帧间隔分布、长停顿、触摸丢失/覆盖。
证据主机日志、构建身份、原始串口、用户实屏反馈；差异和未验证项单列。

实屏检查的最小流程

  1. 固定语言、时间和数据，先读首屏：标题、重点数值和主要动作能否立即区分。
  2. 检查四角、中文上下沿、长标题、单位和最大数字，不允许字形破损、重叠或重要信息被裁切。
  3. 完成进入、滚动、触摸按钮、实体按键返回，重复进入后检查位置和状态。
  4. 在等待中返回、快速重复点击、拖出按钮后松手；确认不会产生重复命令或错误落点。
  5. 检查不可用/失败页面仍可退出；页面释放后的两类内存回到合理基线，反复操作无持续增长。

普通文字和操作验收优先使用直接反馈配合串口记录；只有出现难以文字描述的视觉差异时，再用截图或短视频定位。后续性能基线固定同一正文、字号、亮度、滚动动作和固件身份；输入队列 P95 不能代替刷新性能数据。
