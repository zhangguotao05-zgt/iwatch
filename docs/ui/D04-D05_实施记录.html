2. D04 时间基础

core/iw_time.[ch] 不直接依赖 RT-Thread、RTC 或 LVGL。唯一 owner 传入 32 位原始 tick；模块用无符号差扩展为 64 位毫秒，并保留除法余数，避免 32.768 kHz 等时基持续截断。相邻采样必须短于一整轮 tick，运行时每秒至少采样一次。

ClockSnapshot 同时给出 mono_ms、utc_ms、offset_minutes、revision、valid 与 source。UTC 与时区偏移分别保存，计时期限只使用单调时间。可接受日期为 2000-01-01 00:00:00 至 2099-12-31 23:59:59 UTC，时区偏移范围为 −840 至 +840 分钟；非法日期、revision 耗尽和加法溢出均显式返回错误。

platform/iw_time_rtc.[ch] 使用 SF32LB58 RTC 备份寄存器 29、30 保存“时间状态字及其按位反码”，寄存器 31、28 保存“服务 session 及其按位反码”。固定 SDK 的公共 RTC_BACKUP 枚举目前只占 0–11。写时间时先撤销可信标记，RTC 写成功后再写入并回读状态字；任一步失败都不会把时间声明为可信。session 记录完整时在软件复位后确定递增；备份域丢失或记录不完整时由 TRNG 生成非零 31 位新基值，再恢复递增。31 位随机值只降低冷启动碰撞概率，不能保证与历史 session 不同，也不承担正确性或安全保证；完全断电会同时清除全部 RAM 命令和客户端状态。

开发板没有独立保持本项目 RTC 备份域的供电条件。完全断电后无法推断断电时长，因此时钟回到 invalid 是预期保护行为；系统不会用闪存中的旧秒值伪造当前时间。后续佩戴版若要求断电仍走时，必须在电源设计中保证 RTC/AON 域持续供电，并单独测量保持电流和晶振误差。

旧演示代码的 set_date(2022, 7, 1) 和 set_time(9, 0, 0) 已删除。表盘读取服务时钟；有效时按 UTC 加显式时区偏移显示，无效时只展示本次会话的单调时间，等待 D10 的正式“待校时”页面。

3. D05 命令与快照服务

services/iw_service.[ch] 是纯 C 模型。命令按值复制且固定为 32 B；当前只开放 SET_CLOCK，其 12 B 载荷为 utc_seconds:u32、offset_minutes:i16、flags:u16 和 expected_revision:u32。载荷使用小端具名编解码函数，不依赖未对齐结构强转。

服务按 (session_id, request_id) 识别请求。同 token、同内容重投返回原状态；同 token、不同内容返回冲突；已 ACK 并回收的旧 token 返回过期；旧 session 返回会话变化。命令只有在队列、账本和活动容量全部可保留时才受理，拒绝不产生 RTC 或模型副作用。revision 冲突与 revision 耗尽都在写 RTC 前终结。

结果固定为 48 B，带独立 ledger_generation。页面 generation 只决定 Presenter 是否消费结果，不能阻止全局消息泵 ACK。结果账本共 32 槽，命令队列和同时活动命令上限均为 16；账本无可回收槽时拒绝新请求，不覆盖未确认终态。

快照统一使用 24 B 头，包含版本、topic、头/载荷长度、session、revision 与 flags。当前 topic 为 CLOCK、CAPABILITIES 和 SERVICE。调用方容量不足时只得到 required 字节数，输出缓冲区保持不变。能力项固定为 12 B，当前登记 CLOCK、RTC_BACKUP、DISPLAY 和 STORAGE，状态为 UNKNOWN、AVAILABLE、DEGRADED、ABSENT 或 FAULT。

4. 启动、线程与资源

platform/iw_boot.[ch] 是本阶段唯一启动协调入口。app_watch_init() 先建立静态应用线程对象，再由 iw_boot_init() 创建 GUI 唤醒对象和服务运行时，最后启动应用线程，避免两个自动入口重复创建状态。

对象配置所有权
iw_service 线程优先级 17，静态栈 4096 B，时间片 10唯一命令执行者；每批最多 8 条，每秒至少采样一次 tick。
模型互斥锁RT-Thread priority mutex仅保护有界模型复制和状态转换；RTC 设备访问在锁外执行。
服务事件命令到达锁存；批次后若仍有工作则重新发送避免因一次批次上限留下命令而永久休眠。
固定数据32 个账本槽、16 个队列索引、8 个能力项本阶段不为命令或结果动态分配堆内存。

失败所有权已经固定：应用线程对象初始化失败时尚未进入 boot；boot 初始化失败会撤销本次创建的 GUI 事件和服务资源；线程启动失败只分离未启动的应用线程，保留已就绪且属于设备生命周期的 boot 资源，重试可直接复用。主机故障注入分别覆盖服务初始化失败和线程启动失败后的再次调用，不会在已分离事件上等待。

诊断入口为 iw_clock_stat、iw_service_stat、iw_clock_set <utc_seconds> <offset_minutes> 和 iw_clock_result。校时命令经过正式提交、执行、结果查询和 ACK 路径，不直接绕过服务修改模型。
