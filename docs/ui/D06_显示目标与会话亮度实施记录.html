2. 命令与状态契约

IW_OPCODE_SET_BRIGHTNESS=0x0002。12 B 小端载荷依次为 level:u8、kind:u8、reserved:u16、expected_revision:u32 和 setting_sequence:u32。亮度范围固定为 5–100；kind 只允许 PREVIEW 或 FINAL；reserved 必须为 0；revision 和 sequence 必须非零。

受理前要求 DISPLAY 能力为 AVAILABLE 或 DEGRADED，并同时检查 session、请求高水位、队列、活动命令和账本容量。非法值、容量不足、revision 冲突、revision/sequence 耗尽均不会修改目标模型或调用设备。新命令在主题 revision 达到 UINT32_MAX-1 时拒绝，为 desired 更新和完成结果各保留一次版本增长；所有亮度状态先写入候选快照，确认 revision 仍可增长后再一次性提交，因此失败不会留下部分更新。

亮度快照 payload 固定为 32 B，包含主题 revision、desired_revision、applied_revision、persisted_revision、目标和实际 sequence、last_error 以及三个值和 flags。目标受理、实际应用变化和当前目标错误变化都会增加主题 revision；迟到结果不能把 applied 版本倒退，revision 饱和后 note/finish 也不能静默改变快照。

状态更新时机本阶段保证
desired命令通过容量、能力、revision 和 sequence 检查后立即更新。始终表示当前最新目标。
appliedGUI owner 得到驱动成功后更新。失败、busy 或 timeout 不伪造成功。
persistedD06 不写。flag 无效且保留 SESSION_ONLY，重启回到默认 100。
last_error当前目标应用失败时更新，当前目标成功时清零。旧目标迟到错误不覆盖新目标状态。

3. 显示所有权与 mailbox

platform/iw_display.[ch] 提供不依赖 RT-Thread 的纯 C mailbox 和驱动确认适配器。结构中只有一个 pending 请求和一个 in-flight 请求；运行时使用服务模型的 priority mutex 串行访问，mailbox 自身不另建锁。服务线程不调用 LCD，也不等待 GUI 或 DMA。

  1. 服务从命令队列取出亮度工作，发布到 mailbox。更大的 sequence 替换尚未取走的 pending；被替换命令以 SUPERSEDED 终结并保留在账本中，直到客户端 ACK。
  2. GUI 循环在输入处理之后、LVGL timer 之前取出 pending。已有 in-flight 时返回 BUSY，不覆盖执行中的请求。
  3. GUI 先读取 LCD 状态并查询 busy，再同步执行 RTGRAPHIC_CTRL_SET_BRIGHTNESS；写入后复检状态，并要求 RTGRAPHIC_CTRL_GET_BRIGHTNESS 与目标一致。只有全部确认才返回 OK，NONE/NOT_FIND/TIMEOUT/BUSY、查询失败或回读不一致分别映射为失败结果。
  4. 完成必须同时匹配 session、request、ledger generation 和 setting sequence。成功后清除 in-flight；旧 token 或错误 sequence 被拒绝。

诊断统计记录 posted、replaced、taken、completed、stale、最大已接受 sequence、pending/in-flight，以及四类实际执行结果。所有计数饱和于 UINT32_MAX，不会回绕成较小值。

4. 首次显示、唤醒与恢复

watch_demo.c 中的首次亮屏、触摸唤醒 reassert 和 draw fault 恢复不再写固定局部亮度。三条路径都先读取当前 desired、desired revision 和 setting sequence，再由同一个 GUI owner 设备函数执行完整确认序列；返回结果随后更新 applied 或 last_error。代码中的 100 只保留为模型会话默认值。

驱动调用超过 250 ms 会记录慢调用告警，但该阈值只用于诊断，不会从另一线程取消正在执行的 LCD 操作。显示应用成功把 DISPLAY 能力置为 AVAILABLE；timeout 或 failed 置为 DEGRADED，允许用户再次提交；busy 不改变能力状态。D16 再加入恢复确认、有限重试、尝试/成功/失败拆分计数和最终受控重启。

FinSH 提供 iw_brightness_set <5..100> <preview|final>、iw_brightness_result 和 iw_brightness_stat。命令通过正式服务链路提交；result 查询后执行 ACK；stat 同时显示目标/实际/持久版本、sequence、flags、last_error、mailbox 深度和四类执行计数。诊断命令 iw_display_fault_once <busy|timeout|failed> 只影响下一条 mailbox 请求，用于验证结果链路，不模拟物理 LCD 故障。
