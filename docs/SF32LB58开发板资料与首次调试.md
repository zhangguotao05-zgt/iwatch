## 选对 QSPI 板型

SDK v2.5.1 已提供专门的 QSPI 配置；本套装应按实际存储型号选择以下目标。不要因为开发板名称带 LCD，就套用 DSI/DPI 屏的配置。

| 板上模组标识 | 外部资源 Flash | 合封 PSRAM 总量 | SDK 板型 |
|---|---|---|---|
| SF32LB58-MOD-A128R32N1 | 128 MB QSPI NAND | 16 MB + 16 MB | `sf32lb58-lcd_a128r32n1_qspi` |
| SF32LB58-MOD-N16R32N1 | 16 MB QSPI NOR | 16 MB + 16 MB | `sf32lb58-lcd_n16r32n1_qspi` |

两种模组还有 1 MB 合封 NOR。V1.0.1 官方配置采用 **SF32LB586VDD36**，外部晶体为 **48 MHz 和 32.768 kHz**；晶体频率不等于应用运行主频。首次调试保持对应 BSP 的默认时钟和存储配置。

依据：[官方板型指南](https://wiki.sifli.com/board/devkit_guide.html)、[A128 板型说明](https://github.com/OpenSiFli/SiFli-SDK/blob/v2.5.1/customer/boards/sf32lb58-lcd_a128r32n1_qspi/doc/index.md)、[A128 配置](https://github.com/OpenSiFli/SiFli-SDK/blob/v2.5.1/customer/boards/sf32lb58-lcd_a128r32n1_qspi/hcpu/board.conf)、[N16 配置](https://github.com/OpenSiFli/SiFli-SDK/blob/v2.5.1/customer/boards/sf32lb58-lcd_n16r32n1_qspi/hcpu/board.conf)。

## 屏幕、触摸与手表 UI 示例

A128 QSPI 板型的官方说明明确写出默认转接屏为 `LCD_1P85_390*450_DevKit_Adapter_V1.0.0`。两种 QSPI 板型配置均启用 CO5300 显示驱动，并将触摸设备总线设为 `i2c4`。

| 内容 | 固定 v2.5.1 的源码入口 |
|---|---|
| CO5300 显示驱动 | [customer/peripherals/display/co5300/co5300.c](https://github.com/OpenSiFli/SiFli-SDK/blob/v2.5.1/customer/peripherals/display/co5300/co5300.c) |
| 原套装标注的 FT6146 触摸驱动 | [customer/peripherals/touch_panel/ft6146](https://github.com/OpenSiFli/SiFli-SDK/tree/v2.5.1/customer/peripherals/touch_panel/ft6146) |
| 后续 CWS05 对应的 CST820 驱动 | [customer/peripherals/touch_panel/cst820](https://github.com/OpenSiFli/SiFli-SDK/tree/v2.5.1/customer/peripherals/touch_panel/cst820) |
| LVGL 9 手表界面 | [example/multimedia/lvgl/watch_v9](https://github.com/OpenSiFli/SiFli-SDK/tree/v2.5.1/example/multimedia/lvgl/watch_v9) |

`watch_v9` 自带蜂窝菜单、表盘和立方体旋转演示，是本项目验证界面效果的起点。官方 [GCC 构建配置](https://github.com/OpenSiFli/SiFli-SDK/blob/v2.5.1/build_config_gcc.yaml) 明确列出了该示例与上述两种 QSPI 板型的组合；这是官方配置证据，本项目尚未实测。

SDK 中存在驱动不等于任意同主控屏都能直接替换。原开发套装与拟选 CWS05 的触摸芯片、供电、连接器和初始化参数需要分别核对。CWS05 接口问题继续以 [已有评估](../hardware/CWS05屏幕与佩戴版修订评估/评估与修订方向.md) 为准。

首次界面内存预算可以从 RGB565 开始：390×450 单帧为 **351,000 字节，约 343 KiB**，双帧约 **686 KiB**；这只是像素缓冲，不包含字体、图片、渲染临时内存和任务栈。模组标称 32 MB PSRAM 也不代表这些容量都已分配给 HCPU 的同一个可用堆。

另外，[SiFli Solution 板级介绍](https://docs.sifli.com/projects/solution/open-source-community/board_introduction.html) 还提供更完整的手表应用方案，明确包含 SF32LB58 + 390×450 QSPI 配置。Solution 是独立工程体系，工程路径和依赖版本应按其自身文档选择；首次点亮可先用上述 SDK 示例。

## 首次调试顺序

1. 记录板上模组型号、PCB 版本和屏幕转接板标识，核对套装连接方式。保留出厂程序运行画面及日志，作为硬件工作的基准。
2. 使用数据线连接板上的 **USB-to-UART** 口，在 Windows 设备管理器确认串口。板上另一个 USB 功能口也能供电，但首次串口下载应使用 USB-to-UART。
3. 按 CodeKit 或固定版本 Windows 文档准备 SDK v2.5.1 环境。通过 Git 取得 SDK 时要初始化子模块；GitHub 的普通源码 ZIP 不包含全部子模块内容。
4. 先验证串口日志和最小示例，再编译 `watch_v9`。验证下载流程时，按实物板版本的指南设置 Mode 跳线；官方指南规定插上为下载模式，取下为正常运行模式，模式切换后重新复位/上电。
5. 在官方界面上检查整屏颜色、刷新、四角触摸坐标和滑动方向，然后开始自定义表盘、菜单与转场。

当 SDK 和工具链安装完成、终端已执行该 SDK 根目录下的 `export.ps1` 后，可在 SDK 的 `example/multimedia/lvgl/watch_v9/project` 目录编译。例如实际为 A128R32N1 时：

```powershell
scons --board=sf32lb58-lcd_a128r32n1_qspi -j8
```

实际为 N16R32N1 时，改用 `--board=sf32lb58-lcd_n16r32n1_qspi`。此处提供编译入口，未执行编译或烧录；后续应使用生成的下载脚本/工具和实际 COM 口，不预填固定串口号或下载地址。
